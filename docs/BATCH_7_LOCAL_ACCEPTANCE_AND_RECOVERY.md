这是破坏性**测试库**操作：必须先释放 3002 和 5500；入口会从零重建 `mowo_b1_test`。它先以 `ONLINE_CHECKOUT_ENABLED=false` 验证在线付款保持关闭，并验证社区、线上财务、牛量/推广、模拟认证和创作者自助旧路径对三类调用者、六种 HTTP 方法统一永久拒绝；随后只在一次性 3002 隔离实例中临时开启在线结算，以验证内部订单/库存/生产状态机。测试结束会停止临时服务，日常配置仍关闭在线结算。

## 5. 未来邀请测试的暂停、回退和反馈

### 5.1 必须立即暂停邀请的情况

- 用户能看到他人的账号、地址、素材、订单、合同或生产文件；
- 普通用户或错误岗位能执行后台动作；
- 重复请求导致重复建单、重复扣库存、重复生产或无法解释的数据状态；
- 上传文件绕过类型/所有权限制，或出现恶意文件嫌疑；
- 注销、售后、退款或重要数据恢复无法完成；
- 页面把未开放的付款、退款、社区或创作者收益显示为可用。

暂停动作顺序：停止发放新邀请和测试账号；保留当时提交号、订单号、时间、页面和脱敏截图；停止相关写入口或整个服务；备份现场数据库和必要日志；由负责人判断修复、数据补偿或版本回退。不要通过直接修改数据库“抹平”问题，也不要把已经写入的订单/库存状态随着前端代码一起回滚。

### 5.2 代码和数据回退

- 代码优先用 `git revert <问题提交>` 生成可追踪的反向提交；只有未共享且无业务数据影响的本地实验才考虑切换到先前提交。
- 回退前先停止服务、保存当前 Git 提交号和数据库备份，再按上一已验证提交启动并执行对应冒烟。
- 数据恢复只从已经验证的备份恢复到新建空库，核对迁移状态和核心数据指纹后再切换；禁止在唯一数据库上边恢复边试错。
- 订单、库存、支付和生产数据使用状态机补偿或人工审核，不能简单恢复旧备份覆盖已经发生的新业务。

### 5.3 问题反馈最小模板

P0（越权、隐私、数据破坏、资金或重复生产）立即暂停；P1（核心流程无法继续）停止对应功能；P2（文案、布局、非关键体验）记录后继续有限测试。

## 7. 邀请前最终风险清单

当前只达到 L0 本地自测基线，以下项目使“邀请真实用户”继续暂停：

| 优先级 | 风险 | 邀请前要求 |
|---|---|---|
| P0 | 本地存储没有恶意文件/压缩炸弹/病毒隔离扫描 | 接入隔离扫描、失败处置和受控私有对象存储 |
| P0 | B7 只验证本机测试库备份，没有服务器自动备份、PITR、加密和异地恢复 | 建立独立环境并完成真实恢复演练 |
| P0 | 正式主体、隐私政策、用户协议、售后/定制规则未最终确认 | 负责人和专业人士确认并版本化 |
| P0 | 在线支付、验签、退款、对账均未上线 | 邀请阶段继续关闭；真实交易前单独验收 |
| P0 | 售后有用户申请入口但缺少正式后台消费者页面 | 补最小处理闭环，或明确关闭用户申请 |
| P1 | Access Token 仍在浏览器 localStorage，外部脚本/CDN 增加 XSS 影响面 | 收敛第三方资源、建立 CSP，并评估会话存储迁移 |
| P1 | Scheduler 和文件生成仍与 API 同进程，无多实例锁 | 邀请期限制单实例并制定故障责任；扩容前拆 Worker/锁 |
| P1 | `production-inventory.html` 仍消费两个旧批次只读入口 | 决定迁移至正式批次链或整体下线 |
| P1 | 尚无 CI、集中错误监控、告警和正式问题处理责任人 | 邀请前至少建立自动门禁和故障通知 |
| P1 | 小程序的订单、地址、通知、支付等仍未完成 | 不把小程序列入当前邀请范围 |

在这些风险未按邀请范围处理前，B7 通过只能解释为“本机合成数据可重复运行”，不能解释为“可接收真实用户资料或真实订单”。
