# 私有文件安全

> 实施日期：2026-08-13。本文件记录第三批“用户上传文件安全”的真实实现与剩余边界。生产、库存、分红和在线合同规则不由本模块定义。

## 简单说明

项目现在不再把“知道一个 OSS 路径”当成查看文件的资格。每个新上传文件先进入 `private_files` 登记表，记录上传者、用途、大小、声明类型、实际识别类型、存储位置、校验状态及绑定的业务记录。业务提交时再次核对文件所有权，查看时按用户本人、员工岗位和业务绑定关系授权。

阿里云 OSS 当前未充值，本地开发使用 `STORAGE_PROVIDER=local`，文件保存在 `content-service/storage/private/`。该目录已加入 `.gitignore`，不会进入代码仓库，也不会由前端静态服务器直接公开。正式环境必须改为 `STORAGE_PROVIDER=oss`，生产配置会拒绝本地存储。

本地前端必须从 `frontend/` 目录启动。若编辑器占用或错误配置了 `5500`，可在该目录使用 `python -m http.server 5501 --bind 127.0.0.1`，然后打开 `http://127.0.0.1:5501/pages/settings.html`；开发环境已允许 `5500` 与 `5501` 访问本地 API。

## 当前存储方式

| 环境 | 配置 | 行为 |
|---|---|---|
| 本地开发 | `STORAGE_PROVIDER=local` | 上传写入电脑私有目录；查看使用五分钟签名链接 |
| 正式环境 | `STORAGE_PROVIDER=oss` | 使用私有 OSS；上传和查看均使用短期签名链接 |

本地和 OSS 共用同一套文件登记、用途、所有权和业务绑定规则。以后恢复阿里云时不需要让业务页面重新设计上传流程。

登录账号的上传防刷分成两道独立计数：10 分钟最多发起 30 次上传操作，同时最多登记 300 个文件。一次 24 帧或 50 帧批量上传只算一次操作，但按真实文件数占用文件额度；这样不会把正常多帧素材误判成 24/50 次恶意操作，也不能靠批量接口绕过文件总量限制。匿名入口仍按一小时文件数量限制。2026-08-29 前使用的 `UPLOAD_ACCOUNT_10_MINUTES` 单桶只保留历史记录，不再参与新请求判断。

## 文件用途与限制

| purpose | 用途 | 允许类型 | 单文件上限 |
|---|---|---|---|
| `AVATAR` | 用户头像 | JPG、PNG、WEBP | 5 MiB |
| `AFTERSALE_EVIDENCE` | 售后凭证 | JPG、PNG、WEBP、GIF | 10 MiB |
| `CONTACT_PORTFOLIO` | 联络作品集 | JPG、PNG、PDF | 20 MiB |
| `CONTACT_RESUME` | 求职简历 | PDF | 10 MiB |
| `CREATOR_FRAME` | 创作者帧图 | 图片 | 10 MiB |
| `CUSTOMIZATION_FRAME` | 用户最终选中的定制帧图 | 图片 | 20 MiB |
| `CUSTOMIZATION_SOURCE` | 定制原图/原视频 | 图片、MP4、WebM、MOV | 200 MiB |
| `CONTRACT` | 合同附件预留 | 图片、PDF | 20 MiB |
| `FRAME_PACK` | 生产帧包预留 | ZIP | 200 MiB |

服务器同时检查文件名扩展名、网页声明类型、声明大小和文件内容开头。`application/octet-stream` 不再作为万能兜底；图片伪装成 PDF 或把任意文件改成 `.png` 会被拒绝。DOCX 本质为 ZIP 容器，当前只识别容器结构，尚未扫描压缩包内部文件。

## 权限规则

1. 普通用户只能申请查看自己的已完成文件。
2. 任何员工都不能查看尚未绑定业务记录的孤立上传，包括负责人。
3. 运营客服可查看已绑定的售后凭证、联络作品集/简历和人工筛帧素材。
4. 生产人员只可查看进入生产业务的定制素材与帧包，不能查看简历或售后图片。
5. 合作运营可查看已绑定的作品集、创作者帧图、合同和帧包。
6. 负责人可查看已经绑定业务记录的文件，但查看行为仍写入安全记录。
7. 临时查看链接当前五分钟有效；安全记录只保存文件记录 ID、结果和操作者，不保存文件内容或明文联系方式。

## 匿名联络附件

联络表单继续允许不注册账号提交。匿名访客在同一个浏览器标签页拥有临时上传身份，只能上传作品集或简历；服务器用不可逆摘要保存该身份。提交联络表单时，附件必须由同一临时身份上传、通过内容校验且尚未绑定其他记录，之后才绑定到该留言。

登录用户提交时，后端从真实登录会话自动绑定账号，不再接受客户端提供的 `submitterUserId`，因此不能冒认其他用户。

## 已接通入口

- 账号设置头像：图片完成上传后，必须再调用“采用为当前头像”接口；服务器确认文件属于当前账号且已校验通过，再在同一事务中更新资料和文件绑定。任意外部 URL 不能再通过资料接口写成头像，未采用的头像文件也不能通过公开头像地址读取。
- 头像自动清理：未采用的头像，以及被新头像替换后解除绑定的旧头像，保留 24 小时后由服务自动删除实际文件；当前正在使用的头像始终带有账号资料绑定，不进入清理范围。清理前会先在数据库抢占该文件，避免与用户点击“确认上传”同时发生时误删刚采用的头像。
- 删除成功后不再保留图片内容，但 `private_files` 中保留 `DELETED` 状态和删除时间，便于排查；本地磁盘或 OSS 删除失败时记为 `DELETE_FAILED`，至少等待 15 分钟后自动重试。任务默认每小时运行、每次最多处理 100 个，可用 `AVATAR_ORPHAN_RETENTION_HOURS` 和 `PRIVATE_FILE_CLEANUP_INTERVAL_MINUTES` 调整。
- 2026-08-13 浏览器实测曾发现设置页给无请求体的 `complete`/`use-as-avatar` 请求错误附加 `application/json`，Fastify 会在进入路由前以“Body cannot be empty”拒绝；现已改为仅在请求确实携带 body 时设置 JSON 类型，并给设置页脚本增加版本标记避免旧缓存。
- 2026-08-13 浏览器实测发现全局 `Cross-Origin-Resource-Policy: same-site` 会阻止 `5500` 静态网页显示 `3001` 返回的头像，控制台表现为 `ERR_BLOCKED_BY_RESPONSE.NotSameSite 302`。当前仅公开头像入口与签名文件读取地址返回 `cross-origin`，普通 API 仍为 `same-site`；详细排查见 `docs/TROUBLESHOOTING.md`。
- 售后质量凭证，并在售后申请创建时绑定。
- 创作者动画帧图，并在新建或更新草稿时核对所有权；动画库通过五分钟预览地址显示第一帧，数据库仍只保存私有 key。
- 买家定制编辑器：浏览器内继续用 `data:`/`blob:` 做即时预览，但进入确认页前会把选中帧图登记为 `CUSTOMIZATION_FRAME`，并把原素材登记为 `CUSTOMIZATION_SOURCE`。自己筛选先形成无公开编号的云端草稿，正式提交后才生成定制编号；人工筛选入口上传原素材后直接提交异步审核。
- 定制素材自动清理：上传完成但没有绑定任何业务记录的中断上传保留 24 小时；未提交定制草稿保留 7 天，到期后删除原素材和选中帧，仅保留已过期状态和时间线说明。正式申请不进入这两类清理。
- 联络页作品集和简历，包括匿名提交。
- 联络后台读取，先核对附件属于当前留言，再生成短期链接并记录查看行为。
- 后台机型和 SKU 示例图继续使用原业务归属接口，不经过用户私有文件通用读取入口。

## 仍待处理

- 定制原素材提交、自己/人工筛选双入口、用户记录和后台接收已经形成首批闭环；工作人员处理、补素材、方案确认和最终价格/订单仍待下一批。
- 创作者已审核联名作品的 ZIP 帧包仍有旧 OSS 专用直传接口，尚未迁移到 `FRAME_PACK` 登记流程。
- 合同初期仍在线下处理，`CONTRACT` 只预留规则，现有合同附件字段尚无正式上传页面。
- 旧数据库中已存在的 OSS key 没有自动补入 `private_files`；迁移历史附件前需按业务表核对归属，不能批量猜测所有者。
- 2026-08-13 修复前产生的未采用头像已纳入相同的 24 小时清理规则；旧的 data URL 动画草稿仍继续保留。确认页可以用当前浏览器仍保存的帧图补传；仅数据库中存在且浏览器原图已丢失的旧草稿不可直接进入新购物车，需要用户重新选择图片。
- 当前只有格式、大小和文件头识别，没有接入杀毒、恶意宏、压缩炸弹、图片解码重写或异步隔离扫描。邀请真实用户上传 DOC/DOCX/ZIP 前仍属于阻断项。
- 本地目录不是正式备份。删除电脑文件或清理项目目录会丢失测试附件；不得在本地模式接收真实用户隐私材料。
- 账号注销传播已完成首版：头像、孤立上传和未形成交易的素材会删除实际文件；正式处理中定制会阻止注销。订单、售后、合同、联名帧包和已下单定制绑定的文件会保留并解除普通账号所有权。联络附件六个月删除和争议冻结仍需在对应业务批次实现。
