# V5 生产与履约层迁移记录

更新日期：2026-09-29

## 1. 当前目标

V5 将仍由旧 HTML 承担的生产批次、打印裁切、扫码生产和库存能力迁移到 Vue，并保持服务端状态机、岗位权限、库存副作用和页面功能等价。迁移不是重新设计业务页面；候选页必须与旧页逐项对照，通过后再切入口和物理删除旧实现。

V4 已迁移的后台订单页继续负责地址导出、面单绑定、生产资料导出、返工和发货阶段展示。V5 不复制第二套订单工作台。

## 2. V5-0 运行事实与拆分结论

| 切片 | 当前正式旧实现 | 迁移边界 |
|---|---|---|
| V5-A 生产批次 | `admin-production-batches.html`、`/api/admin/production-batches/*` | 候选订单、风险确认、整单入批、批次详情、打印队列、材料需求和进度；先补持久化创建幂等 |
| V5-B 打印裁切 | `admin-print-production.html`、`/api/admin/print-production/*` | 打印组、逐 SKU 规则、模板版本、排序和冻结快照；迁移前复查组/模板创建的响应丢失重试风险 |
| V5-C 扫码生产 | `production-scan.html`、`production-scan-workbench.js`、`/api/admin/production-workflow/*` | 批次概览、帧包、领料、配对、装箱和发货扫码；保留手输、重复扫描、弱网和服务端确认结果 |
| V5-D 库存域 | `admin-inventory.html` 及库存/材料 API | 不复制约 2600 行七域巨页；按 SKU 库存/渠道配额/流水、原料批次/组装、退料/帧包等可验收领域拆分，共享筛选、表格和弹窗 |

`production-inventory.html` 仍读取旧批次汇总接口，尚未删除。其消费者与替代入口在 V5-D 实施前单独确认，不能随其他页面顺手删除。

## 3. 已识别风险与门槛

1. 生产批次创建此前只有“订单不能进入两个活动批次”的业务冲突保护，没有客户端请求键。服务端提交成功但响应丢失时，重试只能得到冲突，操作员无法可靠恢复原批次。V5-A 前置改为 `clientRequestId + requestFingerprint` 持久化幂等：同岗位、同键、同内容返回原批次；改写内容或跨操作员复用均拒绝。
2. 首次因风险提醒被拒绝时不写批次；确认风险后可以沿用同一请求键。成功后网络重试不再生成第二批，也不再次生成生产文件。
3. 打印组和模板写接口的持久化幂等尚未确认，属于 V5-B 候选前置，不能只依靠按钮禁用。
4. 扫码迁移必须继续依赖服务端幂等和库存事务，前端不得先乐观改变状态。重复扫描、刷新和重试不应重复扣减、配对、装箱或发货。
5. 库存页拆分只改变前端职责边界，不改变库存账本含义。每个写操作必须核对操作人、审计、事务、并发和回归清理。

## 4. V5-A0 生产批次创建幂等契约

- 请求必须携带不超过 80 字符的 `clientRequestId`。
- 指纹冻结排序后的总订单 ID 和 `acknowledgeWarnings`；同键不同指纹返回 `IDEMPOTENCY_KEY_CONFLICT`。
- 唯一键在数据库层防止并发双建；相同请求重放返回原 `batchId` 和 `reused: true`。
- 旧候选页在会话存储中按所选订单保存请求键。风险确认、网络失败后的重试以及页面刷新后重新选择同一组订单均复用该键；成功后清除。
- 历史批次迁移为 `legacy-<batchId>`，不删除旧批次或修改既有生产关系。
- 回归必须同时证明：提醒前不写入、确认后只创建一次、同键同内容恢复原批次、同键改内容拒绝、新键重复入批仍由活动批次规则拒绝。

## 5. 执行与验收顺序

1. 完成 V5-A0 Schema、迁移、服务端契约和真实隔离库回归。
2. 建立 V5-A Vue 候选，逐项对照旧生产批次页；负责人确认后才切入口和删除旧页。
3. 依次执行 V5-B、V5-C；每个切片都遵循候选、自动验证、人工确认、切换、物理删除。
4. V5-D 按库存子域逐批迁移，不一次替换全部库存能力。
5. 最后用标准测试订单完成批次、打印、领料、扫码、配对、装箱、发货和返工闭环，并验证重复操作没有重复副作用。

本文件只记录已经核实的运行事实和已完成证据。页面观感或真实业务路径未经负责人测试时，不能以自动化结果代替人工确认。

## 6. V5-A0 完成证据（2026-09-29）

第 69 份向前迁移已在隔离库 `mowo_b1_test` 应用，既有批次只补兼容请求标识，不删除订单、生产件、帧包或文件。Prisma Schema、104 个服务端脚本语法和 Vue 正式构建通过。

真实生产批次检查通过提醒确认、整单入批、PB/PU 冻结、打印顺序、生产件锁定，并新增三项结论：同键同内容重放返回同一 PB 且 `reused: true`；同键改写确认状态返回冲突；新键对已入批订单仍被活动批次规则拒绝。受字段与调用契约影响的打印排产、扫码幂等/库存副作用、生产文件及指定页返工回归也全部通过。

返工文件脚本首次复跑暴露其仍遗漏 V4-E2 已强制的 `clientRequestId`，真实接口因此正确返回 400；测试请求补齐现行契约后完整通过。该修正不改变返工业务实现，也未掩盖首次失败。所有脚本均使用隔离库并在 `finally` 清理测试账号、订单、批次、资产和文件。本阶段没有创建用户定制草稿。

下一步为 V5-A 生产批次 Vue 候选迁移。旧页仍是正式入口，候选完成和负责人视觉/交互确认前不得切换或删除。
