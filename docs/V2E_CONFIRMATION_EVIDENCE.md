# V2-E 定制确认与购物车闭环证据

> 状态：2026-09-21 E0–E4 已完成。Vue `/app/customize/confirm` 已接管三类正式入口，旧 `customize-confirm.html` 已物理删除；旧 URL 仅保留带查询参数的临时 302。

## 1. 阶段目标

在不改变已确认页面外观、文案和交易状态机的前提下，由 Vue `/app/customize/confirm` 接管规格选择，并把三类入口安全交接到现有购物车和 `checkout.html`：

1. 自己筛帧草稿：`CustomizationRequest(DRAFT)` → `CONFIRMED`；
2. 人工筛帧结果：`FRAME_ACCEPTED / STYLE_SELECTED` → `CONFIRMED`；
3. 私人动画复购：基于当前不可变动画版本创建一份新的已确认定制记录。

V2-E 不新建第二套订单、结算、支付或生产状态。

## 2. 入口与事实源矩阵

| 模式 | 唯一入口标识 | 可信事实 | 允许状态 | 提交接口 |
| --- | --- | --- | --- | --- |
| 自己筛帧 | `requestId` | 本人 `CustomizationRequest`、关联 `CustomProduct`、当前启用机型/SKU | `DRAFT`；重复响应可读 `CONFIRMED` | `POST /api/customization-requests/:id/submit` |
| 人工筛帧 | `humanRequestId` | 本人申请、已接受动画版本、关联 `CustomProduct`、当前启用机型/SKU | `FRAME_ACCEPTED`、`STYLE_SELECTED`；重复响应可读 `CONFIRMED` | `POST /api/customization-requests/mine/:id/choose-sku` |
| 动画复购 | `assetId + modelId` | 本人 ACTIVE 私人动画的当前版本、当前启用机型/SKU | 当前版本帧数必须整除目标 SKU 帧数 | `POST /api/animation-assets/:id/reuse` |

网址中的模式 ID 必须互斥。请求/动画与机型、帧数、版本、归属均由服务端或白名单 API 重新读取；`modelName`、`frames`、`targets` 及 Local Storage 只可作为迁移兼容信息，不能覆盖可信事实。

## 3. 必须保留的页面行为

- 固定四步进度条，第三步“选款式”激活；
- 桌面三栏、手机预览与选配并排且价格卡换行；
- 按帧数 → 尺寸 → 材质 → 颜色逐级筛选；
- 只显示与基础动画帧数整数倍兼容且仍启用的 SKU；
- 可加入多款配置、移除、显示合计和备注；
- 提交成功后把本次购物车条目编号写入 `mowo_checkout_items`，继续交接现有 `checkout.html`；
- 公共导航、登录弹窗、头像菜单继续复用 Vue 共享壳。

旧页的“检测历史同机型订单并直接复用帧文件”与当前正式“我的动画 → 选择新款式”能力重复，且依赖宽泛的历史草稿读取，不迁入 Vue。动画复购只接受明确的 `assetId`。

## 4. 已确认风险与处理

### E-01 路由与浏览器缓存串线

旧页在 URL 缺参时回退多个 Local Storage 编号，旧人工申请可能污染新自助流程。Vue 必须要求明确且互斥的入口标识；正式入口均已能提供该标识。兼容缓存写满、缺失或陈旧时不得创建第二份记录。

### E-02 重复提交增加购物车数量

定制状态接口已有状态幂等，但旧 `/api/cart/add` 对相同商品会叠加数量。按钮禁用无法覆盖响应丢失、刷新、双标签页或并发请求。正式切换前必须建立用户绑定的服务端加购幂等键，并验证同键重放和并发竞争只产生一次购物车影响。

### E-03 分段失败恢复

状态确认成功而加购失败时，刷新后应复用同一已确认请求和同一加购幂等键继续，不得重新生成动画版本、定制申请或定制品。服务端确认上下文必须允许本人读取可恢复的 `CONFIRMED` 状态。

### E-04 旧页面冗余交易叙事

旧页面仍保留未被当前调用的“订单已创建、联系客服付款”弹窗、复制编号和外链逻辑。Vue 不迁移这组死代码；当前唯一后续路径是购物车与现有结算页。

### E-05 直接接口与对象越权

确认上下文、状态推进、动画复购和加购均必须在服务端重新验证用户归属、当前启用机型/SKU、帧数兼容及请求状态。客户端隐藏选项不构成授权。

## 5. 分段与删除门

1. **E0 证据冻结（已完成）**：固定三种模式、页面行为、状态机和风险。
2. **E1 服务端边界（已完成）**：提供确认页白名单上下文；补齐用户绑定的加购幂等与失败恢复测试。
3. **E2 Vue 等价页面（已完成）**：迁移原 DOM/CSS 与逐级选配，复用共享导航、会话和 API 客户端。
4. **E3 闭环回归（已完成）**：覆盖三种模式、刷新恢复、存储已满、并发重放、跨账号和移动端。
5. **E4 入口切换与删除（已完成）**：切换全部入口，物理删除旧确认页，保留旧 URL 临时 302，并以部署检查阻止旧文件复活。

## 6. 删除结论

删除门已于 2026-09-21 全部满足：三类入口均指向 Vue；状态确认和加购具有服务端幂等；结算收到唯一购物车条目；负责人已完成 E2 初步检查；旧地址有保留查询参数的临时 302，部署检查同时要求旧文件不存在。`frontend/pages/customize-confirm.html` 已物理删除。旧 `frontend/js/private-upload.js` 仍由后台共享编辑器使用，不属于确认页专属文件，待 V4/V5 迁移两个后台模式后再删除。
