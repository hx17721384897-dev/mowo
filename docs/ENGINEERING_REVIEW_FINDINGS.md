> 作用：统一接收 RP0～RP7C 的发现，并追踪到决定、整改和验证关闭。

## 状态定义

| 状态 | 含义 |
|---|---|
| `OPEN` | 事实和风险已确认，尚未安排处置 |
| `DECISION_REQUIRED` | 技术事实已明确，但需要负责人决定业务规则或接受风险 |
| `PLANNED` | 已进入整改路线图，尚未开始 |
| `FIXING` | 正在整改，必须绑定责任人与目标切片 |
| `FIXED` | 已有修复，但尚未完成独立验证 |
| `VERIFIED` | 修复和相关回归证据均通过 |
| `ACCEPTED_RISK` | 具名责任人限期接受，包含缓解与复核日期 |
| `SUPERSEDED` | 被另一条发现或设计决定替代 |

## 使用规则

- 这里只登记有代码、配置、数据、运行或文档证据的发现，不把猜测登记成缺陷。
- RP0 的文档矛盾可以登记；RP1～RP7C 的技术发现必须提供可复查位置或命令。
- `FIXED` 不等于关闭，只有验证人与原修复证据相互独立且回归通过后才能标记 `VERIFIED`。
- P0/P1 发现立即汇报；不得等阶段结束后批量隐藏风险。
- `ACCEPTED_RISK` 必须填写接受人、原因、有效期、临时缓解、监控和到期复核日。
- 受订单在途改动影响的条目写明稳定 commit 前不得下最终结论。
