# 动画资产、订单与生产编号框架

> 确认日期：2026-08-21。
> 本文是跨越 Web 定制、动画资产、交易、库存和生产的目标设计，不表示当前代码已经全部实现。代码现状和差异仍分别以 `docs/modules/` 下的调查文档为准。

> 实施进度：2026-08-21 已完成第一批“动画资产与不可变版本”，包括 `ANM` 编号、两条定制确认入口、前台软删除、联名删除拦截、旧数据补建和“我的动画”资产/草稿分离。复购、订单商品和生产结构仍未实现，代码事实见 `docs/modules/animation-assets.md`。

## 简单说明

系统需要把“动画内容”“一次定制过程”“一次付款”“订单中的商品”“要生产的每件实物”和“工厂领用的材料”分开记录。它们相互关联，但不能共用一个编号。

这样设计以后，同一套四帧动画可以先制作十二帧产品，未来再购买十六帧或二十四帧产品；旧订单仍然使用当时确认的旧版本，不会因为用户后来重新编辑动画而变化。

## 已确认业务规则

1. 同一位用户可以长期保留已经完成的动画资产，并用它再次购买其他兼容 SKU。
2. 上传的视频、GIF、原始图片组属于临时素材；长期复购依赖最终确认的核心帧和编辑结果，不依赖永久保存全部原素材。
3. 用户可以在前台删除自己的私人动画资产。删除后不再展示、编辑或用于新下单，但后台仍受控留存必要的动画内容和历史关系；用户不能通过普通前台恢复。
4. 已经成为联名款的动画和对应商品不能由用户删除，只能按联名合同和平台规则下架、停止销售或归档，并保留历史版本及订单关系。
5. 动画修改后形成新版本。旧版本不可覆盖；旧订单和已生成的生产文件继续引用成交时锁定的旧版本。
6. 一次付款在用户侧展示为一个订单。订单可以包含多个商品；每件实物分别生成生产任务和生产编号。
7. 私人定制帧素材包全部按已付款订单现做，不允许提前批量生产。
8. 联名帧素材只有在平台获得相应授权后才允许提前生产；是否备货取决于创作者影响力、作品质量、销售预测和市场反响。没有库存时仍可转为按单生产。
9. 标准材料包可以提前批量生产。首版按“材料包 SKU + 生产批次 + 箱码/库位码 + 数量”管理，不要求每一个普通材料包都贴独立码。
10. 每件最终产品必须有独立生产编号。私人定制帧素材包必须与该生产任务明确绑定，防止不同用户的画面错装。

## 页面职责

`my-animations.html` 和 `my-customizations.html` 不应合并为同一种数据：

| 页面/概念 | 用户看到什么 | 管理的对象 |
|---|---|---|
| 我的动画 | 已确认动画预览、版本、可制作款式、再次购买、前台删除 | 可以反复使用的动画资产 |
| 我的定制 | 自己筛帧或人工筛帧的处理进度、调整记录、确认结果、关联订单 | 一次具体定制过程 |

推荐前台统一使用“我的创作”入口，内部提供“动画资产”和“定制记录”两个标签。现有两个页面可以继续保留为两个实现页面，不因统一入口而混用数据。

一个动画资产可以关联多次定制记录和多次订单；一次定制记录最终只确认一个动画版本，但可以继续选择多个兼容 SKU 下单。

## 编号和对象

所有对象使用数据库内部 UUID 作为真实主键。下面的业务编号用于用户、客服、仓库或工厂识别，不能作为访问私有素材的密码。

| 对象 | 建议业务编号 | 简单含义 | 主要关联 |
|---|---|---|---|
| 动画资产 | `ANM-YYYYMMDD-XXXXXX` | 一套可复购的核心动画内容 | 所有人、来源、当前版本 |
| 动画版本 | `ANM-...-V001` | 某次不可覆盖的帧图结果 | 动画资产、核心帧、内容哈希 |
| 定制项目 | 继续使用 `DZ-YYYYMMDD-XXXXXX` | 一次自己筛帧或人工筛帧过程 | 用户、来源素材、确认版本 |
| 标准 SKU | 继续使用现有 SKU 编码 | 尺寸、材质、目标帧数、颜色等商品规格 | 价格、标准材料包规格 |
| 用户订单 | `SO-YYYYMMDD-XXXXXX` | 一次结算和付款 | 用户、地址、总金额、支付 |
| 订单商品 | `OI-...` | 订单里的一种动画版本和 SKU 组合 | 数量、单价快照、版本快照 |
| 单件生产任务 | `PU-...` | 实际要做的一件产品 | 订单商品、序号、生产状态 |
| 打印版本 | `RV-...` | 核心帧适配某个目标 SKU 后的打印文件 | 动画版本、目标帧数、文件哈希 |
| 帧素材包 | `FP-...` | 打印、裁切并装袋后的帧内容 | 单件任务或联名库存批次 |
| 标准材料包批次 | `KB-YYYYMMDD-...` | 同一 SKU 的一批框架/配件 | SKU、数量、质检和供应批次 |
| 箱码/库位码 | `BX-...` | 装载标准材料包的箱子或库位 | 材料包批次、当前位置、可用数量 |
| 生产批次 | `PB-...` | 工厂某次排产集合 | 多个单件生产任务 |
| 物流包裹 | `SHIP-...` | 一次实际发货包裹 | 一个或多个单件生产任务 |

业务编号格式是当前推荐命名，代码改造时还要核对现有订单码、批次号、正版码和打印标签，避免同一含义存在两套正式编号。

## 动画资产与版本

### 动画资产

动画资产代表“这是什么动画”，不代表某次订单，也不代表某个 SKU。它至少需要记录：

- 所有人或权利主体；
- 来源渠道：用户自己筛帧、工作人员代筛、工作人员代创作者录入；
- 私人或联名属性；
- 前台状态：正常、用户已删除、已归档；
- 联名状态：未申请、合作处理中、已授权、已停止销售；
- 当前可编辑版本和创建时间。

用户前台删除私人动画时采用软删除：从用户列表和新下单入口隐藏，撤销普通用户读取权限。后台留存内容只能用于历史订单、售后、争议、安全审计或已确认的业务用途，并限制岗位和记录访问日志。具体后台留存期限仍需在正式上线前结合法律文本和售后周期确认。

联名动画不得执行普通用户删除。联名停止时只能下架或归档，历史订单继续引用成交版本。

### 动画版本

动画版本保存不可变的核心帧顺序、基础帧数、尺寸/比例、编辑配方、文件 key 和内容哈希。用户重新裁剪、替换、排序或调整帧时创建下一版本，不修改上一版本。

订单商品在创建时必须锁定：

- 动画版本 ID；
- 核心帧文件及哈希；
- SKU 和规格快照；
- 成交价格快照；
- 当时使用的打印模板版本。

## 帧数适配和打印版本

核心动画只保存一次。例如核心帧为 `1、2、3、4`：

- 十二帧 SKU：`1、2、3、4` 重复三次；
- 十六帧 SKU：重复四次；
- 二十四帧 SKU：重复六次。

基础兼容条件为 `目标帧数 % 核心帧数 == 0`，但正式判断还必须同时核对机型模板、图片比例、物理尺寸、裁切安全区和 SKU 是否启用。

系统针对“动画版本 + 目标 SKU + 打印模板版本”生成打印版本。已经进入生产的打印文件要保存哈希并冻结；模板后来更新时，旧订单不能无提示地换成新模板。

## 订单与生产拆分

推荐关系如下：

```text
一个用户订单
  -> 多个订单商品
      -> 按购买数量展开为多个单件生产任务
          -> 每件绑定一个打印/帧素材包来源
          -> 每件领用一个标准材料包
          -> 质检完成后进入一个物流包裹
```

例如用户一次购买同一动画的十二帧款 1 件、十六帧款 2 件：

- 用户看到 1 个订单；
- 订单中有 2 条商品；
- 工厂得到 3 个单件生产任务；
- 三件商品可以装在 1 个物流包裹中；
- 任意一件返工或售后不会改变另外两件的状态。

当前代码把 `CustomizeOrder` 同时当作用户订单和单件生产任务，支付后按购物车条目拆成多个用户可见订单。这与目标结构不一致，后续必须迁移为“订单头 + 订单商品 + 单件生产任务”。

## 标准材料包管理

标准材料包是产品框架、木板或其他标准配件的组合，例如“5x5cm 椴木板 12 帧普通款”。首版采用折中追踪方案：

1. 每种标准材料包有 SKU。
2. 每次批量生产或入库形成材料包批次。
3. 箱子或库位贴箱码，记录其中的 SKU、批次和数量。
4. 员工领料时扫描箱码并确认数量，系统原子扣减库存。
5. 单件生产任务记录实际领用的 SKU、批次、箱码、数量、操作人和时间。
6. 普通低价值材料包暂不逐个贴码；高价值、特殊规格、易混淆或需要严格质量追踪的材料包可以启用单件码。

箱码不是单件产品码。最终成品仍使用独立单件生产编号，以便返工、质检和售后追踪。

## 帧素材包与库存

### 私人定制

- 必须在订单付款并创建单件生产任务后制作；
- 帧素材包使用 `FP` 编号，绑定单件生产任务和锁定的动画版本；
- 包装或周转袋上至少展示生产任务码，装配时再次校验；
- 不进入可供其他订单领取的公共帧包库存。

### 联名作品

- 只有已获得授权的动画版本可以建立预制帧素材库存；
- 可以依据销售预测生成生产计划和联名帧包批次；
- 下单后优先分配可用库存，不足部分自动创建按单生产任务；
- 前台不向用户区分来自库存还是现做，后台必须记录实际来源；
- 联名下架后停止新分配和新生产，已有订单、库存处置和历史记录按合同处理。

## 目标生产流程

1. 用户完成一次结算，系统创建一个用户订单及多条订单商品。
2. 支付确认后，按每条商品数量展开单件生产任务。
3. 每个任务锁定动画版本、SKU、价格和打印模板快照。
4. 系统检查联名成品或帧素材库存；私人定制直接进入现做。
5. 生成或领取对应打印版本，打印、裁切并形成帧素材包。
6. 员工按 SKU、批次和箱码领取标准材料包。
7. 装配前校验单件任务、帧素材包和标准材料包规格。
8. 记录质检、返工、报废和完工结果。
9. 一个或多个完工单件任务组成物流包裹并发货。

## 权限与安全底线

- 普通用户只能访问自己的未删除私人动画，以及自己有权查看的定制和订单结果。
- 业务编号不可用于绕过登录或换取私有文件地址。
- 后台查看私人核心帧、原素材和已删除资产必须按任务及岗位授权，并记录操作人、用途和时间。
- 原始素材、核心帧、打印文件和用户预览图使用不同存储用途，分别设置生命周期和读取权限。
- 生产员工只获得当前任务所需的素材和收件信息，不获得整库浏览能力。
- 联名授权状态必须由后台受控变更，普通用户不能自行把私人资产改成可批量生产的联名资产。

## 当前代码映射和差异

| 目标对象 | 当前最接近模型 | 主要问题 |
|---|---|---|
| 动画资产/版本 | `CustomProduct`、旧 `Animation`、`CustomizationFrameSelection` | 草稿、资产、版本和旧商品概念重叠，没有统一资产主表 |
| 定制项目 | `CustomizationRequest` | 已有独立 `DZ` 编号和版本关系，可继续作为流程记录 |
| 用户订单 | `PreOrder`、`CustomizeOrder` | 支付前有聚合记录，支付后缺少正式聚合订单头 |
| 订单商品 | `CartItem`、`CustomizeOrder` | 没有稳定的成交商品层和金额快照 |
| 单件生产任务 | `CustomizeOrder` | 接近单件任务，但同时被用户订单页直接展示 |
| 打印版本/帧素材包 | `FrameInstance`、`FramePackWork/Variant` | 与订单、动画版本和实体帧包的边界不清楚 |
| 标准材料包 | `MachineModelSku`、`MaterialItem`、`MaterialSkuBinding` | 商品 SKU、标准套件和普通消耗材料尚未清晰分层 |
| 实物绑定 | `OrderItemBinding` | 现有字段不足且当前代码未形成可靠写入闭环 |

## 分批实施顺序

1. **已完成：**建立动画资产和不可变版本，迁移/兼容现有 `CustomProduct`、人工筛帧结果与“我的动画”。
2. 统一“我的创作”入口，完善动画资产和定制记录的导航、重新编辑版本和再次购买入口。
3. 建立正式用户订单、订单商品和单件生产任务，修复一次支付显示多个订单及数量未展开问题。
4. 建立动画版本到目标 SKU 的兼容规则和冻结打印版本。
5. 建立标准材料包 SKU、批次、箱码、领料和原子库存日志。
6. 建立私人帧素材包单件绑定，以及联名帧素材库存/按单生产分配。
7. 重做生产看板、扫码校验、质检、返工、包裹和售后追踪。
8. 完成旧模型迁移、接口兼容清理、自动测试、人工验收和文档回写。

每一批开始前都要先核对现有数据和页面消费者；在新结构通过迁移与回归测试前，不直接删除旧表或旧接口。

## 后续仍需确认

以下问题不阻止先建立上述骨架，但必须在对应批次编码前确认：

1. 用户前台删除私人动画后，后台内容的准确留存期限、允许访问的岗位及彻底清理条件。
2. 未购买但已完成筛帧的动画保存多久、普通用户和创作者各允许保存多少套。
3. 动画版本重新编辑时，是否允许从任意旧版本分叉，还是只能从当前版本继续编辑。
4. 标准材料包在哪一步从可用库存转为领用、损耗、返工或退回，以及盘点差异如何审批。
5. 联名预制库存按“帧素材包”还是“完整成品”备货的具体比例与处置规则。
6. 现有订单号、批次号、正版码中哪些继续保留，哪些只作为旧数据兼容字段。
