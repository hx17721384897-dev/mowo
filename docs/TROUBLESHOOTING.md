# 本地开发常见故障排查

> 本文记录已经真实发生并解决的问题。先按症状定位，不要用删除数据库、重置代码或全局关闭安全规则来试错。

## 同一订单出现两个生产批次

原因通常是先创建了正式 `PB-...`，随后又从旧订单页面导出地址；旧版会额外创建时间格式批次并覆盖单件任务的 `batchId`。2026-08-26 起，正式批次订单会被旧地址导出和旧面单录入接口拒绝。生产操作应统一回到“生产批次”页面。历史测试数据需要以 `ProductionBatchOrder` 和 `ProductionBatchUnit` 的正式关系为准修复，不能直接删除仍有关联的正式批次。

## 头像为空且控制台显示 NotSameSite 302

### 症状

- 数据库 `user_profiles.avatar_url` 有值，头像区域却只显示背景色或破图标。
- 浏览器控制台出现 `net::ERR_BLOCKED_BY_RESPONSE.NotSameSite 302 (Found)`。
- 请求通常指向 `/api/upload/public/:id`。

### 原因

本地静态网页运行在 `127.0.0.1:5500`，API 和文件读取运行在 `127.0.0.1:3001`。头像入口先返回 `302`，再跳转到带签名的本地文件地址。若全局响应头把所有资源都设为 `Cross-Origin-Resource-Policy: same-site`，Chromium 可能在跨端口嵌入图片时拦截这次跳转。

### 当前修复

- 普通 API 继续返回 `Cross-Origin-Resource-Policy: same-site`。
- 仅 `GET /api/upload/public/:id` 和经过签名校验的 `GET /api/storage/local` 返回 `cross-origin`。
- 公开头像接口仍要求文件为 `READY`、用途为头像并已绑定用户资料。
- 私有文件地址仍要求有效签名、有效期和文件状态；`cross-origin` 不等于取消授权。

### 快速确认

1. 在“网络”中点击头像请求。
2. 确认最初请求为 `302`，最终图片为 `200 image/jpeg` 或其他允许的图片类型。
3. 两次响应的 `Cross-Origin-Resource-Policy` 都应为 `cross-origin`。
4. 普通接口 `/api/config/features` 仍应为 `same-site`。

不要把所有 API 全局改成 `cross-origin`；那会扩大不必要的资源嵌入范围。

## 上传头像提示 Body cannot be empty

### 症状

裁剪后点击确认上传，页面提示 `Body cannot be empty when content-type is set to 'application/json'`。

### 原因与修复

前端曾给没有请求体的 `complete` 和 `use-as-avatar` 请求附加 JSON 类型，Fastify 会在进入业务处理前拒绝。公共请求工具现仅在确实存在 body 时添加 `Content-Type: application/json`。若旧页面仍报错，先确认打开的是当前项目目录，再按 `Ctrl + F5` 清除旧脚本缓存。

## 管理员入口或头像突然与预期不一致

### 优先检查

本机曾同时运行两套静态网页：

- 当前标准地址：`http://127.0.0.1:5500/mowo/frontend/pages/`
- 从 `frontend/` 单独启动时可能出现：`http://127.0.0.1:5501/pages/`

两个端口拥有各自的 Local Storage，会表现为不同登录状态；若它们又提供不同版本的 HTML/JS，就会出现一个页面有后台入口、另一个没有。测试期间固定使用 `5500` 标准地址，关闭 `5501` 页面，并按 `Ctrl + F5` 强制刷新。

若仍异常，再依次核对：`3001` 是否运行、`GET /api/v1/account/me` 是否为 `200`、返回的 `staffRole` 是否正确、头像最终请求是否为 `200`。重启只能解决进程未运行，不能修复数据库角色、错误页面目录或响应头配置。

### 负责人能看到“进入后台”，点击却不跳转

负责人账号 `17721384897` 的数据库岗位为 `OWNER` 时，菜单会显示后台入口。这个入口曾使用内嵌 JavaScript 点击函数，当前已改成直接指向 `admin-orders.html` 的普通网页链接。

曾出现点击后短暂打开后台又返回首页：网络记录会依次出现 `admin-orders.html` 和 `index.html`，而 `/api/v1/account/me` 与后台接口均返回 `200`。原因不是权限失败，而是订单页的身份初始化和左侧菜单生成同时进行；身份初始化偶尔先完成，在菜单元素尚未生成时填写姓名会报错，旧代码又把这个界面错误误当成身份错误并跳回首页。当前订单页仅在服务端明确返回“不是工作人员”时跳回首页，菜单尚未生成时不再报错。

同类问题也曾影响款式管理、库存管理、联名审核等后台旧页面。这些页面各自注册了页面初始化，同时依赖公共左侧菜单中的 `sidebarName`、`sidebarRole` 和 `sidebarAvatar`。公共菜单现在会在脚本加载时同步生成稳定骨架，再异步加载岗位菜单和功能开关，因此页面初始化无论先后都能找到这些元素。此修复覆盖所有引用 `admin-sidebar.js` 的后台页面，不需要逐页放宽权限。

处理顺序：固定打开 `5500` 标准地址，按 `Ctrl + F5`，重新登录后再点击。若地址栏完全没有变化，检查入口是否为 `<a href="admin-orders.html">`；若网络记录依次出现后台和首页，则检查 `/api/v1/account/me` 的状态。只有该请求为 `401/403` 或返回的 `staffRole` 为空时才属于登录或权限问题；请求为 `200` 时应继续查后台页面的初始化错误，不应直接修改数据库岗位。

## 本地测试手机号提示当天验证码次数已达上限

### 原因

验证码每日上限是防止短信轰炸和恶意消耗费用的正式安全规则，不应为了测试而全局调高。旧发送顺序还会让 60 秒内的重复点击先占用每日额度，再提示发送太频繁，因此测试账号可能在没有收到十次验证码时提前到达上限。

### 当前修复

- 发送前先检查 60 秒冷却，再消耗每日和网络额度；被冷却拦截的重复点击不再占用每日次数。
- 本地 Mock 环境增加按手机号清理测试状态的命令；生产环境和真实短信模式会拒绝执行。

```powershell
cd C:\Users\25839\Desktop\mowo\mowo\content-service
npm run test-sms:reset -- 18800009101
```

可以一次填写多个号码，例如在后面继续加 `18800009102 18800009103`。该命令不会删除账号、订单、头像或其他业务资料，只会清理这些号码的验证码和对应限流记录。

## 未登录打开“联系我们”却提示必须登录

“联系我们”是公开联络入口，匿名访客应能提交画师合作、渠道、媒体、招聘、反馈和工厂合作信息。服务端会通过 IP 限流、垃圾内容识别和匿名上传会话保护入口；登录只用于把留言关联到现有账号，不是提交前提。前端曾额外拦截表单并强制登录，现已移除。匿名附件仍必须属于同一个浏览器会话，并在提交留言后绑定到该留言。

## 注销任务恢复提示 Body cannot be empty

恢复和重试操作只需要任务编号，请求本身没有 JSON 内容。若前端在空请求上仍添加 `Content-Type: application/json`，Fastify 会在进入恢复逻辑前返回 `Body cannot be empty when content-type is set to 'application/json'`。当前后台操作工具仅在确实存在请求内容时添加 JSON 类型和请求体；暂停操作有原因内容，仍正常发送 JSON。

## 自己筛帧后点击下一步又回到上传页

### 症状

- 少量图片可能正常，图片组或视频抽出较多帧后，点击“下一步”不能稳定进入选款式页。
- 刷新或重新打开后又显示上传素材，或者选款式页提示找不到本次定制草稿。

### 原因与当前修复

旧流程会把筛选后的完整图片数据写进浏览器 `localStorage`。浏览器通常只给每个网站约数 MB 空间，图片组或视频帧很容易超过上限；写入失败还会连带阻止款式信息和草稿编号保存。

当前流程不再把 `mowo_customize_frames` 写入浏览器，只保存后端私有文件 key 和轻量业务信息。上传页完成云端草稿后，会把 `requestId`、款式和帧数放进下一页网址；选款式页优先读取本次网址参数，因此旧缓存或缓存已满都不会把用户退回上传页。

### 快速确认

1. 使用图片组或视频完成筛帧并点击“下一步”。
2. 地址应进入 `customize-confirm.html`，并包含非空的 `requestId`。
3. 在开发者工具“应用程序”中的 Local Storage 检查，不应出现 `mowo_customize_frames`。
4. 若仍显示旧行为，先在当前页面按 `Ctrl + F5`，再确认网页使用标准 `5500` 地址、后端 `3001` 正常运行。
