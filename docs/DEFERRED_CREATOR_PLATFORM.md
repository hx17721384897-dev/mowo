# 延后重建：创作者平台

> 状态：当前版本不提供。2026-09-14 R1-B 已从运行代码与当前 Schema 终态中物理删除旧页面、API、任务及无消费者数据结构；Git 历史只用于追溯，不能作为恢复方案。

## B1 保留边界

- 普通用户的定制流程与 Vue `/app/account/animations`：这是基础定制能力，不等同于创作者后台。
- 公开联名货架与详情：只展示工作人员审核、配置并上架的作品。
- 后台联名作品管理：工作人员仍可审核、配置展示素材、SKU 和上架状态。
- 人工创作者合作：通过联络表单进入，由工作人员线下确认资质、授权、优惠和作品资料。

## 已物理移除的旧能力

- 创作者认证及认证状态页面。
- 创作者动画库、自助联名申请/修改、帧素材包上传和自主定价。
- 创作者通知、收益/提现、分红/储备金、牛量和引流链接。
- 上述能力的创作者端、后台配套页面和专用 HTTP 路由。

## 后续版本重建前置条件

1. **身份模型**：创作者资质不能复用后台岗位角色；需要可审核、可撤销、可留痕的独立资格状态。
2. **授权与作品治理**：作品权属、授权范围、素材来源、版本、审核、下架和申诉需形成状态机与审计记录。
3. **创作者主页**：以审核通过的公开资料和已上架联名作品组成；统一使用公开货架详情，不接回社区/旧商品接口。
4. **合作流程**：先定义人工邀请或申请入口、审核 SLA、合同/授权确认，才能开放自助上传和提交联名。
5. **权益与财务**：优惠、价格、分润、提现、税务与对账必须先有书面业务规则、权限隔离、金额快照和可测试的结算闭环；不能恢复旧页面或旧接口即视为上线。
6. **通知与引流**：通知类别、数据保留、外链校验、内容审核和反作弊规则应独立设计。

## 恢复顺序建议

1. 工作人员邀请的创作者资料与只读公开主页；
2. 受控的作品资料提交与人工审核；
3. 创作者工作台（只读作品状态和通知）；
4. 经审计的权益、统计与财务能力。

每一阶段都须重新建立 API 契约、权限矩阵、独立测试库验收和安全发布边界；不得从 Git 历史直接复制旧实现上线，也不得为了复活旧代码重新增加总开关。
