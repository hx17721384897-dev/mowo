# 项目工程化与架构整理计划

> 版本：v1.2（2026-09-09）
>
> 本计划的当前目标是让哞屋在**本地使用合成测试数据可重复跑通**，并完成架构、权限、数据库、测试、文档和交接基础整理；当前不以邀请真实用户、服务器部署或接入真实线上支付为完成条件。每一批次都必须可独立验证、提交和回退。

## 1. 已确认的产品目标

哞屋是一个将动画内容制作成实体动画机的商品与履约平台：

1. 用户可以浏览并购买联名动画商品，也可以提交素材制作私人动画。
2. 两类商品共享统一的购物车、交易准备、订单、库存与生产履约边界。
3. Web 是浏览、定制和生成付款前订单的主要入口；未来由微信小程序完成身份确认、支付、订单查询和通知。
4. 已付款订单进入统一的生产批次、打印、领料、扫码、装箱和发货流程。
5. 社区互动、线上创作者分红/提现、牛量和 CRMEB 不属于当前本地基础功能范围，必须保持关闭或明确标注为未开放。

## 2. 当前阶段目标：本地自测跑通

当前只执行本地内部演练。邀请测试保留为后续里程碑，不能与本轮完成标准混为一谈。

| 阶段 | 用户和数据 | 允许的事 | 不允许的事 | 最低工程等级 |
|---|---|---|---|---|
| L0 本地自测（当前） | 仅项目负责人/开发者、合成数据 | 验证页面、订单、生产、后台操作和失败回退 | 真实用户资料、真实收款、对外交付承诺 | R0 可重复开发 |
| B1 邀请测试（未来） | 少量受邀真实用户；可能含手机号、素材、地址 | 验证定制、人工处理、订单确认与内部履约 | 真实线上支付、公开注册、社区/线上财务功能 | R1 可安全邀请 |

本轮以 **L0 本地自测可重复跑通** 为完成条件。所有自动检查和人工操作只使用隔离数据库与合成数据。一旦未来决定接收真实手机号、视频/图片、地址、简历或作品集，必须另行启动 B1 邀请测试准备并达到 R1，不能沿用本轮“本地已通过”的结论直接邀请用户。

## 3. 不把“换 Vue”当成架构整理的全部

Vue 3 + TypeScript 适合逐步承接购物车、结算、订单、定制编辑器和管理后台等复杂交互页面，但不是当前本地自测的前置条件，也不应一次性重写整个网站。

当前阶段的优先级是：先固定接口契约、权限、数据与测试基线；再抽取公共 Web 能力；最后按页面价值和变更频率逐页迁移。静态介绍、协议、帮助页面可以继续保持静态 HTML，只要链接、样式、安全策略和部署方式受控。

企业级可维护性由以下能力共同决定：

- 清楚的产品范围与业务状态机。
- 可复现的数据库迁移、环境配置和依赖安装。
- 明确的后端领域边界、API 契约、权限和错误处理。
- 身份、私有文件、输入、日志和密钥的安全基线。
- 自动测试、持续集成、发布门禁与可回滚的 Git 历史。
- 备份、恢复、监控、告警和操作手册。
- 能让新程序员理解“现在真实如何运行”的文档，而非只保留历史规划。

## 4. 执行原则

### 4.1 先事实、后改动

- 当前代码、Prisma Schema、迁移、运行检查和实际前端消费者优先于旧规划文档。
- 业务规则未确认时，记录问题，不擅自把候选方案写进生产逻辑。
- 不为追求整洁而删除仍有消费者、数据迁移责任或追溯价值的旧代码。

### 4.2 小批次、可验证、可回退

每个批次必须：

1. 写明目标、范围、排除项与验收条件。
2. 在开始前保存 Git 基线；只在本批专用分支或清晰提交上工作。
3. 同步修改代码、测试和对应事实文档。
4. 运行自动检查与关键人工回归。
5. 用单一主题提交保存；通过后创建带日期和批次号的 Git tag。

禁止将无关的界面微调、格式化、临时目录、生成文件或另一批业务改动混进同一个提交。`.codex-tmp/` 与 `content-service/.codex-tmp/` 始终不作为产品代码提交。

### 4.3 先收口，再重写

先建立唯一的入口、唯一的服务端事实源和兼容期边界，再删除旧实现。对 Web 前端采用渐进迁移；对交易、库存、生产等高风险模块先统一状态与数据，再考虑代码形态。

### 4.4 每项审计必须留下可交接记录

审计不以“存在页面或接口”判定功能完成。每个功能、页面、路由或数据域都使用以下统一标签：

| 标签 | 含义 |
|---|---|
| 可用 | 有正式入口、服务端校验、数据写入、实际消费者和测试/人工验证闭环。 |
| 可用但有限制 | 主路径可用，但受人工步骤、功能范围或未覆盖异常限制。 |
| 未完成 | 只有页面、接口、Schema 或规划的一部分，无法完成业务闭环。 |
| 新旧冲突 | 两套入口、模型、状态或接口承担相同职责。 |
| 关闭但保留 | 当前不开放，但有未来业务、数据兼容或追溯价值。 |
| 可归档候选 | 无正式入口、消费者、数据责任和近期业务价值；仍不直接删除。 |
| 安全/上线阻断 | 在 B1 接收真实用户资料前必须处理。 |
| 待业务确认 | 代码不能决定规则，必须由项目负责人确认后才修改。 |

每条记录至少写明：业务职责、入口和消费者、路由/API、数据模型和迁移、权限与功能开关、测试证据、已知冲突、推荐动作、风险级别及最后核对日期。代码存在但被关闭的社群、线上财务、牛量、提现等能力，一律先归为“关闭但保留”，核对入口、消费者、数据与风险后再决定迁移、归档或恢复；不得因暂时无用而顺手删除。

## 5. 本地自测完成标准

完成当前 L0 阶段前，以下项目必须满足：

| 责任域 | L0 完成标准 |
|---|---|
| 范围 | 首页、定制、联名展示、人工处理、订单确认和内部生产入口的开放/关闭状态可由服务端与前端共同验证；未开放功能无可用入口。 |
| 环境 | 新电脑按文档可安装依赖、配置环境、从空库建立数据库并启动服务。开发、测试与未来生产的配置不混用。 |
| 数据库 | 当前 Schema 有可重放的迁移基线；空库迁移、种子（如需要）和核心冒烟检查有记录。 |
| 身份与权限 | 新旧认证入口有明确边界；普通用户、客服、生产、运营、负责人只能访问职责所需数据与动作。 |
| 文件与隐私 | 合成素材、头像和订单文件按所有者、用途和岗位授权；上传有限制、临时读取可追踪。真实附件扫描或隔离方案保留为未来 B1 前置条件。 |
| Web 主流程 | 本地测试账号可完成登录、浏览、定制或提交人工筛帧、查看自己的处理结果和订单状态；后台可完成对应人工操作。 |
| 测试 | 基础检查、关键 API 权限/契约测试，以及 Web 核心浏览器回归可重复运行。 |
| 运行 | 有本地健康检查、脱敏日志、启动/停止/重建测试库和回退说明；不要求本轮购买服务器或建立线上告警。 |
| 告知 | 本地页面不得把未开放的支付、退款、社区、创作者财务或小程序能力显示为已经可用。正式协议与隐私文本保留为未来 B1 前置条件。 |

真实支付、退款、正式微信支付、公开注册、容量扩展、线上分账和公开上线不属于本轮验收。
