# OPEN_QUESTIONS.md - 待确认问题

本文件只收集会改变产品规则、兼容策略、安全边界或数据处理方式的问题。纯技术上可从代码查明的问题不放在这里。

## 当前讨论原则

当前阶段的首要目标是把各模块已有能力、原规划、代码差异、风险和所有需要负责人决定的事项记录全面。此阶段只优先确认首发范围、业务边界、数据责任和安全底线；表单字段、按钮布局、审批级数、状态名称、金额公式等实现细节，除非会阻断整体架构选择，否则留到实际开发对应模块时结合完整流程再讨论。延后细节必须继续保留在问题台账中，不能因暂不讨论而遗漏或被当作已经解决。

## 上线准备问题的处理顺序

- `Q-004/Q-045/Q-051` 是一组域名、微信主体和环境拓扑问题：B1 接收真实资料前确定 Web/API/OSS 基础拓扑，C 真实交易前补齐微信 AppID、商户和支付回调配置。
- `Q-046` 在 B1 前需要有负责人和可发布的用户协议/隐私政策；定制退换、标准商品退换、配送和退款承诺最晚在 C 前确认。页面现有文案不自动成为已批准政策。
- `Q-052/Q-053/Q-054` 当前不要求负责人给出假精确数字。技术侧先为 B1/C 提出保守流量、恢复和最低安全成本假设；D 前再以压测、真实使用和预算校准。
- `Q-055` 分阶段落实：B1 前至少明确业务负责人、技术执行人和数据访问名单；C 前明确支付/退款/订单事故责任；D 前形成发布审批、告警值班和对外事故决策。
- `Q-056` 的开发/测试数据隔离属于 R0/R1 基线；正式独立预发、支付沙盒、发布和回滚演练在 C/D 前完成。
- `Q-013/Q-043` 属于开发前架构收口：修改交易和联名详情功能时确定，不阻断当前文档梳理。

详细阶段门槛、复杂度和责任域见 `LAUNCH_READINESS.md`。

| 定制审核演进 | 后续监管需要加强时，再为私人定制增加自动风险检查、提示、抽检或必要人工复核；启用范围、申诉方式和误判处理须在上线前另行确认，当前首版不阻断下单。 |
| Q-001、Q-048 登录方式 | Web 浏览、上传和简单预览不要求登录，保存云端草稿或提交订单时使用手机号短信验证码登录。首发不向用户开放密码注册/登录，但保留可选密码字段和未来恢复能力；旧密码公网接口应关闭或置于默认关闭的功能开关后，不能因“以后可能需要”而继续暴露。微信小程序首发使用微信身份，付款前绑定并验证手机号，以同一手机号关联 Web 需求与小程序账号。 |
| 扫码订单关联 | Web 订单码只携带不可猜测、短期有效的兑换凭证，不携带手机号、价格、素材地址或用户 ID。用户扫码进入小程序后完成微信登录，首次付款前验证手机号；只有与 Web 需求提交账号一致时才展示订单、素材和地址。手机号不一致时不泄露订单内容，转身份验证或人工客服处理。 |
| Q-003 退出登录 | 普通“退出登录”只退出当前浏览器或手机；账户安全另提供“退出全部设备”。后端需要区分并撤销单个会话与用户全部会话。 |
| 企业微信与订单 | 企业微信只承担素材/版权/合作沟通，不作为账号、订单或付款数据库。客服可以向用户发送与该需求对应的小程序订单入口（小程序卡片、受控链接或二维码）；用户在小程序内完成身份绑定、订单确认和后续付款。 |
| Q-002、Q-007 注销与处理期 | 原 7 天、后续 48 小时设想已于 2026-08-13 进一步修订为 10 分钟防误操作保护期；48 小时仅为异常任务内部处理目标。保护期内可重新登录查看状态并主动撤销；不得上传新定制、购买新商品、提交新的创作者合作、提现或产生其他新责任。登录本身不自动撤销注销。 |
| Q-008 注销前置条件 | 有未完成生产/未收货订单、处理中退款/售后/投诉、未结创作者收益/提现、仍履行的联名合作/合同或其他争议时，不允许申请。系统一次列明所有阻止事项；到期执行前再次检查。 |
| 注销后的数据 | 正式注销后删除或不可逆匿名化手机号、昵称、头像、生日和社交资料；删除未进入生产的素材与草稿。已生产素材在订单、售后和争议期限结束后删除。订单、支付、退款、合同和必要审计记录依法保留并限制用途，不继续公开用户身份；已售联名作品另按合同、历史订单和下架规则处理。 |
| Q-009 未来修改密码 | 未来启用密码后，修改成功保留当前设备登录，撤销其他设备会话；用户仍可主动选择退出全部设备。 |
| Q-010 订单与生产任务 | 用户侧保留一个聚合订单；订单内每一件实物分别生成一条生产/履约任务和独立生产码，以便逐件追踪、返工和售后。同一订单的多件商品可以合并为一个物流包裹发货，生产任务与物流包裹不是同一概念。 |
| Q-011、Q-012 硬件库存 | 已确认的高层方向是相同实体硬件不能由彼此无关的库存口径造成超卖，且库存、生产与订单必须可追踪。此前讨论的“付款预留、扫码转在制、完工转成品、发货只改履约”等仅保留为候选方案，不是最终定案；具体状态、扣减时点、取消和损耗逻辑待实际修改库存/生产模块前，由项目负责人说明完整流程后重新确认。 |
| Q-015 联名备货与现做 | 联名款可根据销售预估提前生产一部分成品库存。前台不向用户区分“预制、现货、现做”，只展示统一商品信息和可信的预计发货时间；后台记录实际履约来源，有可用成品库存时优先分配，库存不足时自动进入现做生产流程。帧包或成品备货不足不直接阻止下单，但必须影响生产排程、库存预警和预计发货时间。 |
| Q-016 数量限制 | 普通线上订单默认限制同一 SKU 每单最多 10 件；超过 10 件引导通过企业微信进入人工大宗订单，由后台创建经确认的批量订单。限量联名款可另设“每位用户在指定活动周期内最多购买数量”，由服务端按账号及必要的防绕过标识校验，不能只依赖前端。 |
| 取消、退款与定制例外 | 未付款订单可直接取消；已付款但未开工可申请取消和退款。个性化定制一旦进入生产，不支持无理由取消，但质量问题、成品与确认内容明显不符或平台责任仍可申请售后；标准联名商品按普通实物商品规则处理。定制例外必须在付款前显著展示并由用户主动确认，不能只写在隐藏条款中。 |
| 生产模块讨论边界 | 项目现有代码已经包含订单编号、批次、生产状态、扫码和追踪相关设计，当前任务首先是如实整理现状及其连接关系，不把文档不完整误判为功能完全不存在。生产和库存的完整业务意图较复杂，Q-033 至 Q-041 暂不作最终产品决定；待实际修改该模块前，由项目负责人说明完整流程后再更新。当前权限最小化、用户资料脱敏、原图访问留痕、状态纠错审计等内容只作为安全检查项保留。 |
| Q-005、Q-006 联络附件边界 | 首发保留画师/IP、线下渠道、媒体/博主、加入团队、反馈、厂家六类联络入口。只有画师/IP 作品集和求职简历允许直接上传附件：作品集接受 JPG、PNG、PDF，单文件不超过 20MB；简历只接受 PDF，单文件不超过 10MB。首发拒绝 Word、ZIP、PSD、AI 和可执行文件。其他联络类型先用结构化文字与受控外部链接；合同不经公开表单上传，只允许授权员工从后台上传 PDF 或图片。所有私有对象必须按用途和记录授权，不能用通用 OSS key 换取读取链接。 |
| Q-030 联络身份 | 六类联络都允许未登录提交，以验证码、共享限流和反垃圾策略防滥用。已登录提交由后端依据已验证会话自动绑定账号；匿名提交不绑定平台账号，服务端不信任客户端提供的用户 ID。 |
| Q-032 联络资料留存 | 未建立合作且不再跟进的作品集、简历及其联络附件，在最后一次有效联系后 6 个月自动删除；不再需要识别个人的表单记录做匿名化或删除。已建立正式合作、录用、发生投诉/争议或存在法定义务的材料，应转入相应合同、人事或争议记录，按该记录的独立期限和访问权限保存，不能借“联络表单”无限期留存。 |
| Q-026 至 Q-028 首发内容范围 | 首发通过服务端功能开关关闭文章发布、文章/feed 读取、评论、点赞、收藏和关注，不只隐藏页面入口；代码保留供未来迭代。经平台审核的联名商品展示不属于社区，继续开放。文章发布资格、审核、举报申诉以及 `public/followers/private` 的详细语义，延后到社区真正重启前确定。 |
| Q-029 创作者实名边界 | 当前前端模拟实名和后端信任客户端布尔值的实现不得用于真实认证。普通定制中询问“是否为创作者”只作为合作线索，优惠继续由企业微信人工核实版权和持续原创能力；正式签订联名合同、产生分红或申请提现前，必须通过可靠身份核验。供应商与凭证留存方式在接入前另行确认。 |
| Q-031、Q-050 首发通知 | 首发通知只覆盖人工筛帧处理结果、联名审核结果、订单状态、付款结果、发货、售后和账号安全。站内/小程序消息承载可查询记录；微信订阅消息必须由用户主动授权；短信主要用于验证码及重要安全或订单异常，不发送营销短信；商务联络继续按用户留下的邮箱或企业微信回复。营销消息以后必须单独征得同意，社区互动通知随社区启用再讨论。 |
| Q-017 至 Q-023 联名收益上线阶段 | 首发不启用线上分红率计算、牛量等级、推广归因、创作者余额、提现和收益仪表盘，也不向创作者承诺现有代码已形成可用财务闭环。初期合作分红由平台与创作者线下约定和处理，并在现有管理后台增加仅供授权员工使用的简化合作台账。未来创作者数量增加后再回归线上收益体系，届时每笔收益、结算、提现申请和实际打款必须分别记录，不能用“已结算”表示已经付款。 |
| Q-020 合同与账号 | 初期合同不在线签署，合作方也不必先注册平台账号。合同主体应支持个人、工作室、公司或其他 IP 权利方，平台账号仅为可选关联；后续需要线上查看收益或提现时，再绑定并验证对应账号。 |
| 初期合作创作者标签 | 平台可由员工人工给部分账号标注“合作创作者/优惠资格”，用于开放约定的定制工具能力或标准购买优惠。该标签只是一项内部审核后的平台权益，不代表已完成线上实名、签署线上合同或自动参加分红；具体权限、优惠、审批人和有效期仍需单独确定并留痕。 |
| 初期内部合作台账 | 首发可在现有管理后台内增加仅供授权员工使用的简化合作台账，用于把合作主体、联名作品、线下约定、销售/应付依据、实际付款及凭证关联起来。它不向创作者开放，不提供自主提现，也不等同于未来完整分红系统；具体字段、操作和复核流程在开发该功能时确认。 |
| Q-024 正式记录保留 | 未生效且没有关联资金或履约事实的草稿可以按权限删除；正式合同、结算、付款及其他财务记录不得物理删除，只能作废、归档或以冲正记录纠正，并保留原记录、原因、操作人和时间。 |
| Q-025 联名下架访问 | 联名作品下架后立即从商城、搜索和公开分享入口隐藏。已购买用户仍可在历史订单中查看成交时的商品快照、履约和售后信息，但不能读取创作者原帧；合作创作者和授权员工仅可按合同、运营、生产或售后用途访问必要材料，原帧等私有素材访问必须留痕。 |
