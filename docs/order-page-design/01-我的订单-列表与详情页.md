# mowo 订单页面结构与交互

> 2026-10-14。这里描述首轮页面，不代表已经实现。所有“可操作”均由服务端返回资格并在提交时复核。

## 1. 购物车、结算与付款结果

**购物车每条商品**：来源（私人定制）、作品标题和预览、锁定的动画版本、完整规格路径和 SKU、单价、数量、行金额、库存/价格变化提示。定制作品变更时提示重新确认，不悄悄替换版本。多条商品各自保留独立快照，不能用首条商品代表整单。

**结算页顺序**：收货地址 → 全部商品及规格 → 商品金额/运费/真实调整 → 应付金额 → 支付方式与付款说明 → 提交。点击提交时禁重复，服务端重新计价、校验归属和库存；若结果变化，返回明确差异并请顾客确认。付款窗口失效后显示“已过期，请重新结算”。

**付款结果页**必须分“待付款”“支付确认中”“支付成功”“失败/过期”。成功时显示 SO 订单号和进入详情；网络中断后可凭 PreOrder 查询最终结果。结果未知时只给查状态与求助入口，不鼓励重复付款。模拟付款按钮只在开发测试环境出现，生产页面留未来微信支付位置。

## 2. 我的订单列表

```text
我的订单                            [搜索订单号或商品]
[全部] [待付款] [进行中] [已完成] [已取消] [售后中]

┌ 已付款 · 最早 15:20 可排产 ────────────────┐
│ [作品图] 作品 A · 动画 V2 · SKU 完整规格 ×2 │
│          另有 1 件商品                    │
│ 订单号 SO... · 10月14日 · 实付 ¥...       │
│ [取消订单（符合规则时）] [查看详情]        │
└───────────────────────────────────────────┘
```

| 区块 | 第一轮规则 |
|---|---|
| 筛选 | “进行中”包含已付款、制作中、待发货、运输中；“售后中”可与履约并存，订单卡不重复 |
| 搜索/排序 | 订单号和商品名；最近创建在前；服务端分页，切换筛选后回第一页 |
| 订单卡 | 主状态、最重要的一句说明、订单号/日期、来源、首件商品、剩余件数、实付或应付、主要操作 |
| 操作 | 待付款为继续支付；已付款且可取消为取消；运输中且可确认时为确认收货；其余以查看详情为主 |
| 退款 | 已申请与已退款分别显示，不能把原订单金额改写成“扣掉退款后的金额” |
| 状态 | 付款前 PreOrder 和付款后 SO 在一份列表出现，正式订单生成后原待付款卡被同一交易的 SO 卡替换 |

无订单给“去私人定制”入口；筛选无结果给“查看全部”；加载失败给“重试”；无权限返回统一不可访问说明。卡片内容和按钮在手机窄屏不能遮挡金额或规格。

## 3. 订单详情

```text
返回我的订单        已付款 | 订单号 SO...
已于 14:20 付款；最早 15:20 可进入生产批次
[符合条件时：取消订单]  [联系客服]

进度：付款成功 → 制作中 → 待发货 → 运输中 → 已完成
商品：逐条作品、版本、全部规格/SKU、数量、单价、行金额
费用：商品合计、真实运费/调整、应付、实付、退款中、已退款
收货：成交时的姓名/脱敏电话/地址
生产：已入批时的批次进度摘要；不显示内部工艺数据
物流：实际承运商、运单与发货时间；无记录则说明“尚未发货”
售后：整单申请、审核、退款分别列时间和结果
帮助：带订单号联系客服
```

时间线只显示真实发生的节点和时间，未来节点可写“等待中”而不造时间。订单详情使用成交快照；不要去当前商品表重新拼接价格和图片。多条明细分别展示，生产件数与明细数量相符。订单已入 PB 后，取消按钮消失并说明“已进入制作，如需帮助请申请售后或联系客服”。付款后 60 分钟仅标注“最早可排产”，不承诺自动生产或发货。

## 4. 整单售后

首屏说明这是整单申请，列出订单内全部商品与件数；选择诉求（退款/质量问题）、原因、文字说明、必要凭证（目前最多三张）。提交成功显示申请编号、提交时间和“待审核”；审核通过/拒绝要显示理由与时间。付款退款状态另起一行：待处理、处理中、成功、失败。申请获批不能直接显示“退款成功”。已有处理中申请时不给第二次重复提交入口。

## 5. 商家订单页面

**列表**：订单号、日期、来源、客户脱敏信息、件数/金额、付款、生产、物流、售后、异常标签。支持订单号、时间、状态、来源搜索筛选。把“待我处理”放在显眼处；批量导出仅授权岗位可用。

**详情**：顶部摘要及当前待办；下方是订单明细和快照、支付/退款流水、SO→PU→PB 关联、物流、售后申请、操作时间线。管理员可从订单详情跳生产批次，生产人员从批次回订单。订单后台只做交易与售后操作，生产进度由生产后台写入。每次取消、审核、发货或设置变更需记操作者、时间、理由和结果。

**暂缓设置**：后台设置页显示当前分钟数、适用范围“仅之后付款成功的订单”、修改人和最近修改时间。保存前提示已付款订单保持原时间。生产候选列表明确写“尚需等待 XX 分钟”或其他阻止原因；最终创建批次仍由服务端校验。

## 6. 页面共同验收

- 手机端先看到状态、商品和主按钮；状态有文字，不只靠颜色。
- 按钮提交中不可连点，失败后给真实原因和可重试路径。
- 不展示没有可靠依据的预计送达、包邮、折扣、退款到账时间。
- 用户改订单 ID 无法读到别人的地址、作品或售后凭证。
