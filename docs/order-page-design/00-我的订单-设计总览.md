# mowo「我的订单」与商家订单设计总览

> 2026-10-14。本文与 01—03 组成页面设计包，业务总依据见《04-mowo订单系统重设计.md》。所有页面均为待实现目标，不能把设计稿视为当前代码已完成。

## 顾客要解决的四件事

1. **找得到**：付款前后都能在同一账户找到这笔交易，按订单号/商品搜索，看到历史订单。
2. **看得懂**：准确知道买了哪一版作品、哪组 SKU、花了多少钱、当前处于付款/制作/发货/售后哪个阶段。
3. **能处理**：符合规则时继续付款、整单取消、确认收货或申请整单售后；不可操作时知道原因和下一步。
4. **可追溯**：商家能把 SO、商品明细、PU、PB、付款、库存、物流、售后对起来，操作有记录。

## 第一轮页面地图

| 入口 | 页面 | 首要信息/动作 |
|---|---|---|
| 私人定制、购物车 | 商品确认 | 作品/动画版本、层级规格、数量、价格、库存变化 |
| 结算 | 支付确认 | 地址、费用、付款截止时间、结果查询 |
| 账户 | 我的订单列表 | 状态筛选、搜索、订单卡、下一步 |
| 列表/付款结果 | 订单详情 | 交易快照、付款、最早排产、生产/物流、整单售后 |
| 订单详情 | 售后申请/进度 | 原因、凭证、审核结果、独立退款状态 |
| 商家后台 | 订单列表/详情 | 查单、异常、付款/履约/售后与操作历史 |
| 商家后台 | 生产批次、设置 | 可入批订单、阻止原因、暂缓分钟数 |

顾客初期需登录查询自己的订单。未建好的游客查单、部分退款、多包裹、发票、优惠促销、再次购买不提供操作入口。联名入口以后复用订单框架，先把私人定制验收通过。

## 信息架构

每笔交易分为五层：**购买事实**（商品和规格快照）→ **资金事实**（应付、实付、退款）→ **履约事实**（SO/PU/PB、发货）→ **售后事实**（申请、审核）→ **操作记录**（谁在何时做了什么）。订单主状态只摘要最值得顾客注意的一层，其余事实仍在详情保留。

PU/PB 是内部生产关联，顾客只看对外制作状态，不看任务、批次编号或工序。发货后物流信息在详情顶部优先出现；已决定接入自动轨迹查询/订阅，服务商在接入阶段确定，并保留运单复制与官方查询入口。

所有状态来自服务端。付款成功必须以可信支付事实为准；进入 PB 后才显示“制作中”；退款渠道确认前不能显示“已退款”。最早可排产时间不等于发货承诺。旧商品下架、改价或动画更新都不能修改已成交快照。订单本人以外不可读取地址、私有动画和售后凭证。

## 参考能力与取舍

参考成熟后台的订单搜索/筛选、详情摘要、付款记录、履约记录、退货记录和操作历史：[订单概览](https://docs.medusajs.com/user-guide/orders)、[订单详情](https://docs.medusajs.com/user-guide/orders/manage)、[支付](https://docs.medusajs.com/user-guide/orders/payments)、[履约](https://docs.medusajs.com/user-guide/orders/fulfillments)。mowo 第一轮落地与当前产品有关的能力：整单取消、整单售后、逐件生产追踪和 60 分钟暂缓履约。逐件退换与分包裹等能力只在结构上保留扩展空间。
