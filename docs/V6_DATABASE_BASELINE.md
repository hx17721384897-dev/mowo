# V6-B 日常数据库安全基线

> 完成日期：2026-10-11  
> 结论：本轮仅做本机只读快照、数据库备份和结构比对；`mowo_db` 没有执行迁移、DDL、DML、重建或迁移账本写入。

## 1. 为什么不能直接补跑迁移

日常 `mowo_db` 是项目早期通过直接同步 Schema 和零散增量建立的开发库，并不是从仓库迁移链顺序创建的。它包含当前仍需保留的素材和业务试验数据，也包含已经从运行代码退役的历史表。

因此 `_prisma_migrations` 中的“未登记”不等于对应结构全部缺失。对该库直接执行 `prisma migrate deploy/dev/reset`，可能重复建表、重复加列、触发旧数据约束失败或破坏已有素材关联。V6-B 只登记事实，不授权执行自动生成的修复 SQL。

## 2. 可重复的只读审计入口

在 `content-service/` 执行：

```powershell
# 只读结构审计，不创建新备份
npm run audit:daily-db

# 先生成完整 PostgreSQL custom-format 备份，再执行相同只读审计
npm run audit:daily-db -- --backup
```

安全门槛：

- 只接受本机 `localhost`/`127.0.0.1` 的数据库名 `mowo_db`。
- 参照库固定为同一实例的 `mowo_b1_test`，且必须具有仓库全部 73 份已完成迁移。
- 两个数据库的目录查询和数量查询均在 `REPEATABLE READ READ ONLY` 事务内执行。
- 报告只包含结构元数据和白名单表数量，不写出手机号、地址、文件 Key、订单内容等业务行。
- 报告写入 Git 忽略的 `.local-run/`；备份写入 Git 忽略的 `.local-backups/`，禁止提交或外发。

### 3.1 当前缺失的三张关键表

- `cart_mutations`：购物车加购幂等账本。
- `collab_frame_pack_mutations`：联名帧包库存写入账本。
- `inventory_material_mutations`：材料入库、调整和消耗写入账本。

缺少这些表时，当前代码的响应丢失重试和重复提交保护不能成立。因此日常库目前只能作为历史资料源，不能直接作为当前 Vue/API 的运行库。

### 3.2 当前缺失字段的主要范围

- 定制草稿：`custom_products.client_draft_key`。
- 帧图制作/导入：草稿和导入批次的 `client_request_id`、`request_fingerprint`。
- 库存：`inventory_logs.request_fingerprint` 及材料变更账本全部字段。
- 打印/生产：打印组、模板版本、生产批次、返工记录的请求键和指纹。

同名字段差异中，风险较高的包括：

- `inventory_logs.operator_id` 在日常库允许为空，而目标结构要求非空。
- `production_batches.status` 日常默认值为 `Open`，目标结构为 `READY`。
- `platform_configs.group_name` 日常默认值仍为退役牛量域的 `bull`，目标结构为 `system`。
- `collab_works.shelf_status`、`custom_products.status` 等字段类型或默认表达式与目标不同。

### 3.3 已退役但仍存在的数据表

31 张日常库独有表来自旧社区、认证、创作者财务、提现、分红、储备金、牛量、推广链接和创作者自助商品等能力。运行代码和接口已经退役，但本轮不删除这些表：必须先确认历史关联、制定数据留存/导出规则，并通过独立副本演练向前迁移后才能处理。
