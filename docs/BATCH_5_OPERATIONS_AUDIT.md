## 2. 岗位模型事实与当前风险

服务端的唯一岗位枚举在 `content-service/src/lib/permissions.js`：负责人（OWNER）、运营客服（CUSTOMER_SERVICE）、生产人员（PRODUCTION）、合作运营（COLLAB_OPS）。`content-service/src/index.js` 已对能够映射到后台权限的请求执行统一鉴权，并记录 `request.staffPermission` 供拒绝审计使用。

| 编号 | 事实 | 风险判断 | 处理状态 |
|---|---|---|---|
| B5-001 | 旧路由仍调用 `fastify.requireRole(1/2/3)`，新入口使用 `requiredPermissionForRequest()` 与岗位权限表。 | **P0 可维护性风险：** 两套模型叠加时，岗位表变更后容易误放行或误拒绝。 | **B5 核心已收口：** 用户、岗位、封禁、日志、联络、合同、联名政策已改命名权限；剩余数字判断主要在旧生产/订单域，转 B6 按消费者迁移。 |
| B5-002 | `COLLAB_OPS` 为兼容旧字段映射为数字 role 2，但它不等于客服。 | **P0 回归风险：** 缺失路径映射而仅依赖数字 2 的路由可能越权。 | 员工隔离回归已覆盖合作运营、客服、生产和负责人正反权限；仍需随新增端点持续维护。 |
| B5-003 | 联络普通处理与删除/IP 封禁需要不同权限。 | 若只用 CONTACT，客服可能获得不可逆动作。 | **已修复：** 普通处理使用 `CONTACT`，删除/IP 封禁使用负责人专属 `CONTACT_ADMIN`，隔离回归通过。 |
| B5-004 | 合同、结算记录、联名运营页面仍存在，但创作者自助、创作者财务和牛量不属于当前本地基础功能。 | **P0 产品边界风险：** 管理后台数据录入功能不等于可对外运营/结算能力。 | 17 个已注册关闭端点及 10 个预留前缀已建立自动映射复核；财务/牛量/社区/模拟认证/线上付款仍由服务端关闭。 |
| B5-005 | 多个 `admin-*.html` 曾各自硬编码 `localhost:3001` 或 `127.0.0.1:3001`。 | **P1 维护风险：** 非默认端口或后续环境会请求错误地址。 | **已修复：** 20 个后台页及帧图共享脚本均使用 `runtime-config.js`；新增静态回归防止复发。 |
| B5-006 | 员工权限回归脚本会创建用户、岗位、注销任务和审计日志。 | **P0 测试安全风险：** 不应允许写入 `mowo_db`。 | **已修复并验证：** 仅允许 `mowo_b1_test`，一次性 3002 员工权限回归通过。 |
| B5-007 | 4 个旧页面曾从 JWT payload 读取数字 `role`，仅用于前端跳转/展示。 | **P1 体验与维护风险：** 岗位改动或 Token 刷新时可能误判。 | **已修复并回归：** 后台页面统一读取 `/api/v1/account/me` 当前 `staffRole`；静态检查禁止数字岗位页面判断，逐岗位浏览器正反路径通过。 |
| B5-008 | 后台页面原先没有统一运行时 API Origin。 | **P1 维护风险：** 页面各自判断部署地址。 | **已修复代码：** 20/20 页面加载运行时配置，20/20 加载认证脚本；`check:admin-runtime-config` 通过。 |
| B5-009 | `admin.js` 仍保留一大组以旧 `CustomizeOrder`、旧批次和旧扫码模型为中心的 `/api/admin/orders`、`/batches`、`/scan`、`/auth-codes` 路由。 | **P0 架构边界风险：** 它们与 B3 的正式 `SalesOrder`/生产工作流并存，不能被新后台页面或后续功能重新接入。 | 移交 B6：建立消费者清单、封闭旧入口或迁移数据后才能删除。 |

## 3. 已实施记录（2026-09-09）
