## 1. 首发前风险

### H-01 小程序续期与服务端 Cookie 模型不兼容

小程序请求层在 401 时调用 `/api/v1/auth/refresh`，并假设 `withCredentials` 会携带 HttpOnly Refresh Token；服务端只从 `refresh_token` Cookie 读取凭证。[uni-app 官方 `uni.request` 文档](https://uniapp.dcloud.net.cn/api/request/request.html)说明 `withCredentials` 仅 H5 支持，并提示小程序端不会自动保持 Cookie，因此 Access Token 到期后无法形成可靠续期。对应 `ERF-010`。

### H-02 C 阶段交易交接不是闭环

Web 到小程序受控交接、小程序地址/结算/订单/定制上传/通知页面、微信身份、手机号、真实支付与订阅通知尚未形成一条可验收链路。当前只足以作为开发骨架，不足以支持 C 阶段发布。对应 `ERF-011`。

### H-03 旧资料接口绕过现行资料规则

Vue 正式消费者使用 `/api/v1/account/profile`，但旧 `/api/auth/profile` 仍接受已登录用户调用，并可直接更新头像 URL、昵称和生日等字段，绕过 v1 的文件归属、昵称频率/唯一性和年龄规则。对应 `ERF-012`。

## 2. 版本与契约热点

### H-04 主仓库与小程序没有兼容版本约束

两个工程是独立 Git 仓库；主仓库没有记录可兼容的小程序 commit，也没有共享 OpenAPI/Schema 生成、跨仓库契约测试或联合 CI。任一仓库单独合入都可能使另一个客户端失效。对应 `ERF-013`。

### H-05 DTO 由客户端和路由手工维护

小程序曾出现分页、注册字段和购物车字段漂移；Web 定制接口也存在整行数据库对象响应。RP3/RP4 应建立公开 DTO 白名单和契约测试，不让 Prisma 字段自动成为公网 API。

## 3. 新旧实现热点

### H-06 退役 API 的处理器仍留在运行代码

入口 Hook 会对旧订单、生产、批次、扫码和旧定制订单路径返回 410；但对应处理器仍存在于 `admin.js` 和 `customize-orders.js`。屏障可以阻止访问，却不能替代物理删除。消费者审计完成后，应在 RP8 删除处理器、私有辅助代码和无消费者数据结构。对应 `ERF-014`。

### H-07 人工筛帧仍跨到旧编辑器

Vue 后台将员工交接到唯一旧 HTML。该页自行维护令牌、心跳、自动保存和复杂帧编辑状态，是独立生命周期与安全边界。RP3/RP6 应先建立功能清单和特征测试，再决定等价迁移或限期保留；不得通过逐页复制继续扩大旧体系。

## 4. 领域耦合热点

### H-08 后台综合路由责任过宽

`admin.js` 同时包含用户、注销、日志、售后以及旧订单/生产处理；`production-workflow.js` 同时编排订单、批次、文件、领料、扫码和发货。风险来自责任与事务边界混合，不是单纯文件长。RP4 应先按用例和事务边界补特征测试，再分离协议、领域服务和持久化。

### H-09 定制对象关系部分依赖应用代码

`CustomizationRequest.customProductId` 是字符串而非 Prisma relation/数据库外键；商品删除、请求关闭和两套清理任务已经产生生命周期分裂。动画版本还通过对象键引用帧文件，长期文件责任依赖源对象继续存在。对应 RP1-A 的 `ERF-005`，并由 RP2/RP5继续核查。

### H-10 Scheduler 与 API 进程绑定

所有 API 实例都会启动全部任务，没有统一租约、运行记录、积压和优雅停止。任务内部局部幂等不能证明整批完整或多实例唯一执行。对应 `ERF-007`～`ERF-009`。

### H-11 订单域结论暂时受保护

负责人正在单独修改订单界面和功能。RP1 只记录入口、模型和上下游依赖；待负责人提供稳定 commit 后，必须重新核对订单 DTO、状态机、金额、幂等、库存、支付、生产和日志，不能沿用本次快照下最终结论。

## 5. 后续处理顺序

1. RP2 先冻结产品语义和状态机，尤其是定制/动画、联名上下架、库存/生产和文件生命周期。
2. 订单稳定后补做交易域 RP1/RP2，不覆盖负责人在途改动。
3. RP3/RP4 核对客户端状态所有权、DTO、API、事务和补偿。
4. RP5/RP6 核对数据库约束、文件引用、安全和会话方案。
5. RP7 建立跨仓库契约、日志、真机与故障验收门禁。
6. RP8 才实施修复，并在新实现接管后物理删除兼容残留。
