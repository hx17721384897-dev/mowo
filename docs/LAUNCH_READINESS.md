# LAUNCH_READINESS.md - 上线准备地图

> 调查基准：2026-08-12；当前阶段口径更新：2026-09-09。
>
> 本文回答“从本地自测走到邀请测试、小规模真实交易和公开上线，分别必须补齐什么”。当前工程任务只要求本地使用合成数据可重复跑通；邀请真实用户、服务器部署、正式法律文本和线上备份恢复属于下一阶段，不是本轮完成条件。

## 两条阶段轴

项目同时存在产品发布阶段和工程就绪阶段。为避免字母重复造成误解，统一使用以下命名：

### 产品发布阶段

| 阶段 | 含义 |
|---|---|
| B 邀请测试 | 验证产品介绍、定制上传、人工审核、订单确认和内部处理流程；不强制真实在线收款 |
| C 小规模真实交易 | 少量真实用户通过微信小程序付款，完整经历退款、生产、物流和售后 |
| D 公开上线 | 面向公众持续运营，并具备容量、监控、客服、合规和事故处理能力 |

### 工程就绪等级

| 等级 | 目标 | 典型结果 |
|---|---|---|
| R0 可重复开发 | 新电脑和空数据库可以可靠启动 | 配置模板、完整依赖、迁移基线、基础脚本 |
| R1 可安全邀请 | 可以接收受邀用户的手机号和素材 | 会话、权限、上传授权、隐私告知、日志脱敏、删除机制 |
| R2 可真实交易 | 可以安全收款并对账 | 微信支付、订单/退款/库存一致性、幂等、备份恢复、售后 |
| R3 可稳定发布 | 每次版本可测试、审批、发布和回滚 | CI、预发、自动测试、监控告警、Runbook、职责分工 |
| R4 可规模扩展 | 有证据承载目标流量和故障 | 压测、索引、队列/Worker、多实例、容量预算和演练 |

产品阶段与工程等级不是一一对应：B 的纯内部演练可在 R0 后开始，但只要邀请真实用户上传素材，就必须达到 R1；进入 C 前必须达到 R2，并至少具备 R3 的关键发布和监控能力；进入 D 前应完成 R3，并用真实目标完成 R4 验证。

## 邀请测试再分层

### L0 本地内部演练（当前）

- 只使用团队人员和合成数据，不使用真实客户手机号、地址、简历、合同或受版权保护的生产素材。
- 不真实收款，不对外承诺交付时效。
- 目标是验证页面跳转、人工审核、订单确认和后台操作是否能走通。
- 最低要求是 R0：环境可重复、数据库能从空库建立、测试账号不会混入普通开发库或未来生产。

### B1 受邀真实用户测试（未来）

- 可以接收受邀用户的手机号、定制视频/原图及必要联络信息。
- 即使暂不收款，也已经承担个人信息、版权素材、账号安全和删除请求责任。
- 必须达到 R1：真实协议入口、最小权限、私有上传归属、日志脱敏、验证码防刷、账号注销和数据删除可执行。
- 对“参考价格、人工审核、不可制作、预计回复时间、是否收款”使用清晰且不误导的测试文案。

## 十个上线责任域

### 1. 产品范围与变更控制

- `RELEASE_SCOPE.md` 是当前首发范围总表；新增首发能力必须同步评估许可证、数据、支付、审核和运维成本。
- 社区、线上创作者财务、在线合同、多端发布默认关闭，不能因代码存在而偷偷进入首发。
- 2026-09-07 已将联名商品收口为唯一 `showcase.html` 列表和 `showcase-detail.html` 详情，两套旧详情业务已删除。下一个发布范围风险是混合购物车、结算快照和小程序接力尚未闭环。
- 复杂度：低至中；主要风险是范围反复导致安全和测试基线持续漂移。

### 2. 主体、域名与外部平台

- 需要确定 Web 主域、API 同源反代或可信子域、OSS 资源域名、微信小程序 AppID 和商户主体。
- 当前代码把多个 API 地址写成 localhost 或历史域名，不能直接部署。
- 域名拓扑会影响 Cookie、CORS、CSRF、CSP、上传回调、支付通知和微信合法域名。
- 复杂度：技术中等，主体申请和审核周期属于外部依赖，应提前启动。

### 3. 法律文本与用户告知

- 至少需要用户协议、隐私政策、私人定制使用与不可制作说明、联名上架审核规则、定制退换例外、标准商品退换、配送、售后和注销说明。
- 现有页面存在空链接、把隐私政策指向联系页，以及“全球配送”“支付宝”“7 天无理由退换”等疑似占位且未经负责人确认的展示文案。
- 系统需记录用户同意的文档版本、时间、场景和必要证据；文本内容应由业务负责人和具备相应资质的专业人士最终确认。
- 复杂度：技术中等，文本责任和审查属于外部/组织依赖。

### 4. 身份、权限与内部治理

- Web 短信登录、小程序微信身份与手机号绑定、员工角色和后台权限必须共用清晰账号模型。
- 员工权限需按客服、审核、生产、打包、财务和超级管理员职责拆分；私有素材、收货信息、合同和付款凭证按任务授权。
- 高风险操作至少记录操作者、原因、前后状态、请求 ID 和结果；是否双人复核在开发对应功能时确认。
- 复杂度：中高，横跨几乎全部路由和后台页面。

### 5. 数据、迁移与生命周期

- 第一优先级是建立能从空库部署的当前 Schema 基线，并在 CI/预发重复验证。
- 数据按账号、订单、支付、生产素材、联名原帧、联络附件、合同、审计分类，分别定义访问和删除期限。
- 作品集/简历六个月规则已确认；联系方式、IP/User-Agent、实名凭证仍待确定。
- 备份不等于恢复：需要自动备份、PITR、加密、权限隔离和定期恢复演练。
- 复杂度：中高；目前没有真实用户，是修复迁移和模型边界成本最低的窗口。

### 6. 交易、资金与售后

- 首发采用精简自建订单系统，真实支付只接微信官方能力，不接 CRMEB。
- C 阶段前必须统一服务端报价、订单头/明细、支付回调、退款、库存和售后副作用，所有重试都幂等。
- 线上创作者分红、牛量和提现首发关闭；内部合作台账不能冒充正式支付账本。
- 生产和库存具体流程延后确认，但任何真实交易都必须能够解释每笔钱、每件货和每次状态变化。
- 复杂度：高，是 C 阶段的核心工程风险。

### 7. 文件、内容与版权安全

- 所有上传使用用途限定会话，记录所有者、对象前缀、真实类型、大小、哈希、扫描状态和有效期。
- 原图、帧包、合同、简历和作品集使用不同目录、权限和生命周期；公开 ID 不能换取私有签名 URL。
- B1 即需具备恶意文件、压缩包、超大文件和重复上传防护；社区重启前还需内容审核、举报和申诉体系。
- 复杂度：中高，涉及 OSS、异步扫描、后台权限和数据清理。

### 8. 测试、预发与发布

- 最小门禁包括依赖安装、语法检查、Prisma 校验、空库迁移、API 契约、Web 核心流程和小程序真机清单。
- 预发必须使用独立数据库、OSS 桶和密钥，只使用合成数据；生产数据进入测试必须脱敏并审批。
- 每次生产发布需要可回滚制品、数据库变更顺序、冒烟结果和批准记录。
- 复杂度：中高，但越早建立越能降低后续每个功能的修改成本。

### 9. 性能、容量与韧性

- 先设保守首发和活动峰值假设，再压测匿名浏览、登录、上传、商品列表、结算和后台导出混合场景。
- 指标至少包括吞吐、错误率、P50/P95/P99、Node 堆与事件循环、数据库连接/锁/慢查询和 OSS 延迟。
- 扩容前先把 Scheduler 和 CPU/内存重任务迁到可靠 Worker；Redis、队列和缓存按实际瓶颈引入。
- 复杂度：高，但 D 阶段才要求完整规模证明；B/C 阶段先消除无界查询和单点故障。

### 10. 运营、客服与事故响应

- 明确谁批准发布、保管生产密钥、执行迁移、接收告警、处理退款、回应用户和决定停服/回滚。
- 为误删、密钥泄露、账号盗用、支付异常、库存错账、OSS 泄露和短信滥用建立运行手册。
- 供应商余额、配额、证书和域名到期必须监控，不能等用户报错才发现。
- 复杂度：技术中等、组织决策高；小团队也需要明确主责与替补。

## 剩余宏观决策分类

### 现在可以先不回答

- 精确云资源规格和月预算：待域名/主体与 B1 范围更明确后，用最低安全基线估算。
- 精确 DAU/QPS：当前无真实流量，可先由技术给出保守压测假设，之后用真实数据校准。
- 生产库存、社区、线上分红和自动审核细节：已明确延后到模块开发前。

### 进入 B1 前必须确认

- 是否由现有公司主体承担网站、小程序、短信、OSS 和用户协议责任。
- B1 是否收集真实手机号和真实定制素材；若是，必须完成 R1。
- 用户协议与隐私政策由谁提供最终文本并批准发布。
- 哪些团队成员可以查看真实素材、联系方式和后台数据。

### 进入 C 前必须确认

- 微信小程序和支付使用的主体、AppID、商户号、结算账户及客服责任。
- 定制退换、标准商品退换、退款和配送的最终业务承诺。
- 生产/库存完整流程以及真实退款后如何处理已投入生产的商品。
- 数据库/OSS 备份与恢复目标，以及支付和订单异常由谁处理。

### 进入 D 前必须确认

- 首发和活动峰值、可用性、恢复目标及预算。
- 发布审批、值班、事故分级、对外沟通和供应商续费责任。
- 是否需要更高等级的 WAF、跨区容灾、队列和多实例部署，以压测和风险为依据决定。
