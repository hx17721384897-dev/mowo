# V6-C 最终验收计划、合成数据与后台证据

> 状态：C1 验收设计与可观测性基线已完成；C2～C6 尚未执行。本文是最终验收的唯一执行清单，不能把页面“看起来正常”写成业务通过。

## 1. 验收结论必须由四类证据组成

每个案例都必须同时记录：

1. **页面证据**：桌面 1440px、中宽 900px、手机 390px 的页面结果；涉及文件、扫码或打印时补真实设备结果。
2. **接口证据**：请求方法、路径、状态码、业务错误码和请求键；不得只看按钮提示。
3. **数据证据**：业务表的前后快照、状态转换、数量增减以及重复提交后的记录数。
4. **日志证据**：运行日志、`operation_logs`、`audit_logs` 或领域流水中至少一种可追踪证据；高风险写操作必须有数据库持久化证据，不能只依赖控制台。

判定规则：页面正确但接口、数据库或日志不正确，案例仍为失败；自动测试通过但真实文件/设备未测，只能标记“自动通过、人工待验”。

## 2. 隔离环境和禁止事项

- API 数据库必须是 `mowo_b1_test`，不得连接日常素材库 `mowo_db`。
- 普通阶段以关闭结算模式启动；交易阶段单独用 `-EnableMockPayment` 重启，且只允许模拟支付。
- 每轮使用一个 `runId`，格式 `V6C-YYYYMMDD-HHMM`。所有名称、备注、文件名和请求键均带该前缀。
- 测试前记录相关表数量；测试后按 `runId` 和夹具主键清理并再次计数。不得按模糊名称批量删除。
- 不在文档、截图或提交中保存密码、短信码、Token、Cookie、真实手机号、地址、私有文件 Key、签名 URL 或数据库备份。
- 网络重试必须复用同一个幂等键；只有用户明确发起一笔新业务时才能生成新键。刷新页面不得自动创建草稿、订单、库存流水或生产批次。

## 4. 后台证据与可靠性分级

| 层级 | 当前实现 | 能证明什么 | 不能证明什么 |
| --- | --- | --- | --- |
| L1 运行日志 | Fastify JSON 日志；本地重定向到 `.local-run/api.out.log` 和 `api.err.log` | 请求到达、响应码、未处理异常 | 本地文件没有轮转、集中存储、告警和不可篡改保证 |
| L2 通用操作日志 | 已认证的 POST/PUT/PATCH/DELETE 和后台 401/403 写入 `operation_logs` | 操作者、角色、路径、结果、状态码、会话、IP、UA、脱敏前后摘要 | 在 `onResponse` 中尽力写入；日志失败不会回滚已成功业务 |
| L3 安全审计日志 | 改密、换号、注销、封禁、角色、帧素材等关键操作写入 `audit_logs` | 关键安全事件与目标对象 | 并非每个普通业务动作都有独立命名事件 |
| L4 领域事实 | 幂等账本、库存流水、定制事件、订单/生产状态、模板版本 | 业务副作用和重放结果，是业务正确性的主要证据 | 不能替代运行故障告警和长期审计归档 |

本轮已新增明确的运行日志请求头脱敏，并扩充操作日志对邮箱、对象存储 Key 和签名 URL 的脱敏检查。仍存在两个上线前缺口：

1. 通用 `operation_logs` 是响应后 best-effort 写入。关键写操作必须在同一事务内写 L3/L4 证据；最终矩阵会逐项核对，缺失则修复或阻断上线。
2. 本地日志不是生产可观测性方案。正式上线前必须确定结构化日志收集、保留周期、访问权限、告警和备份；V6 不虚构尚未部署的云日志能力。

只读 GET 默认不创建数据库操作日志。敏感文件下载和后台数据导出必须检查现有显式访问日志；普通公开页面读取只需要 L1 请求证据。

## 5. 页面逐项验收步骤

下面每一行都执行正常、空数据、失败/越权、刷新或重复提交中适用的分支；执行记录必须填写实际状态码和表变化。

### 5.1 官网、登录与法律页（C2）

| 页面 | 操作步骤 | 后台证据 |
| --- | --- | --- |
| `/` | 三视口打开；逐一使用桌面/移动导航；登录后检查头像与菜单；退出后刷新 | `GET /api/config/features`、首页数据请求；登录/退出的会话与安全审计；无业务表新增 |
| `/about`、`/products`、`/faq` | 路由间往返，测导航不抖动；FAQ 搜索命中/无结果；断网后显示可恢复错误 | GET 请求与浏览器错误；不得产生写日志或业务记录 |
| `/contact` | 六类表单分别打开；匿名单次提交；附件类型/大小失败；响应丢失后不误报；后台能看到同一条 | contact 行、上传记录、限流结果和脱敏操作日志；正文不得进入运行日志 |
| `/legal/terms`、`/legal/privacy` | 从登录框和页脚进入；确认草案/版本标识与返回路径 | 只读；登录同意时另查 `consent_records` |

| 页面 | 操作步骤 | 后台证据 |
| --- | --- | --- |
| `/showcase` | 有货、空态、搜索/筛选、破损图片；WORK-OFF 不可购买 | 联名读取 API；加载不得写浏览量以外的草稿/购物车 |

| `/account/settings` | 头像、资料、地址新增/编辑/默认/删除、改密/换号失败分支、注销申请 | 用户/地址前后快照；改密、换号、注销查 `audit_logs`；日志中无密码、码、完整地址 |
| `/account/customizations` | 筛选请求、查看时间线、进入编辑；B 越权读取 A | `customization_events` 和 403/404；只读不新增草稿 |
| `/account/animations` | 查看两个版本、重用、编辑新版本、删除允许/拒绝分支 | 新版本不可改写旧版本；重放不重复；私有文件访问有目标记录 |

### 5.3 私人定制（C3）

1. `/customize`：选择机型；未登录回跳；配额满时阻断；重用素材只显示兼容机型。
2. `/customize/editor` 图片组：上传 12 帧、排序、裁剪、逐帧编辑、保存、刷新继续、返回再进入；同一来源只保留 `CUSTOM-DRAFT` 一条。
3. 同页视频：0.5 秒和 8 秒通过，超限失败；裁剪后进入完整帧编辑；GIF 解帧；不支持格式在上传前拒绝。
4. 人工筛帧：私有上传后提交 `CUSTOM-HUMAN`；生产岗位领取；唯一保留的管理员编辑器筛帧；用户确认或要求返修。
5. `/customize/confirm`：自筛帧、人工结果、动画复用三种来源分别确认；混合来源失败关闭；刷新和响应丢失复用请求键。

后台必须核对 `custom_products`、`customization_requests`、`customization_events`、帧选择、私有文件归属及幂等键；B 不能读取 A 的任何私有源文件。每次刷新前后记录草稿数，最终不得出现重复草稿。

### 5.4 购物车、结算与订单（C3）

1. `/cart`：装入 `CART-MIXED`；改变数量、删除、失效商品、缺货和变价确认；连续双击只产生一次预期变化。
2. 以模拟支付模式重启后进入 `/checkout`：复用地址组件、新增地址、切换默认地址；提交一次并模拟支付；故意丢弃首个响应后用同键重试。
3. 核对只有一个 `PREORDER-A`、一个 `ORDER-A`，库存/锁定/订单项/生产任务金额一致；支付失败事务不得留下半订单。
4. `/orders` 和 `/orders/:id`：混合订单展示、取消允许/拒绝、确认收货、退款/质量售后、物流；B 访问 A 订单必须失败。
5. 下架 WORK-A 后验证：不能新加购，但 ORDER-A 的历史快照和履约不被删除。

证据至少包含预订单请求键、支付事件、订单及订单项、库存锁定/扣减、生产记录、售后记录和对应领域/操作日志。

## 6. 失败、断网、重复提交与安全统一用例

所有包含写操作的页面追加以下检查：

1. 未登录、错误岗位、跨用户目标分别返回 401/403/404，页面不能先乐观显示成功。
2. 请求体缺字段、超长、非法枚举和不存在外键返回 4xx，不泄露 Prisma、堆栈、SQL、磁盘路径或对象存储配置。
3. 第一次请求已落库但响应被丢弃，再发同一请求键，只恢复原结果；同键改内容必须 409。
4. 两个并发相同请求最多产生一个业务副作用；库存不得为负，锁定不得超过实存。
5. 刷新、后退、重新登录不自动提交；失败表单保留可安全重试所需内容，但不把密码/验证码持久化到浏览器。
6. 服务端文本统一按纯文本渲染；上传限制在前后端都校验；签名 URL 过期、跨用户和改 Key 均失败。
7. 检查 `api.err.log` 无未解释 5xx；检查 `operation_logs` 无敏感明文；检查夹具表无孤儿和重复记录。

## 7. 分阶段执行与完成门槛

- **V6-C1（已完成）：** 固定数据目录、证据等级、逐页步骤；补运行日志头部脱敏和操作日志敏感字段测试。
- **V6-C2：** 官网、身份、账户、联名货架；产生第一份实际结果表。
- **V6-C3：** 私人定制、购物车、模拟支付、订单；重点证明无重复草稿/订单。
- **V6-C4：** 素材、机型、联名、客服、用户、安全日志和外部导入边界。
- **V6-C5：** 后台订单、生产、打印、扫码和库存七域；需要真实文件/设备的项单独标记。
