# DOC_CODE_DIFFERENCES.md - 文档与代码差异台账

> 用途：保留历史信息，同时防止后续开发把旧数字、规划接口或“已完成”标记误当成当前代码事实。
> 规则：只记录可验证差异；没有确认产品意图前，不删除原文档，也不擅自选择其中一套实现。

## 状态定义

- `确认差异`：当前代码与文档可以直接对照，内容不同。
- `过渡并存`：新旧实现同时存在，暂不能直接删除任一方。
- `文档滞后`：代码已扩展，文档没有同步。
- `待验证`：还需检查迁移、前端消费者、运行环境或生产数据。
- `部分解决`：已完成一部分整改，条目保留尚未完成的边界。
- `已解决`：对应代码缺口已整改并通过当前可执行检查，仍保留历史记录。
