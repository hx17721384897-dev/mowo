## 1. 纠偏目标

Vue 重构只替换技术架构，不自行重新设计产品。迁移后的页面应在相同数据、视口和状态下，与迁移前正式页面保持相同的信息结构、视觉语言和主要交互；只允许删除已经确认退役的社区、线上财务、牛量、创作者自助等能力，以及虚假数据、不安全实现和不成立的承诺。

“一比一”包括但不限于：导航、页脚、内容顺序、宽度、留白、字号、字重、颜色、边框、圆角、阴影、列数、瀑布流、悬停、加载骨架、空状态、错误状态、移动菜单、固定/粘性区域、媒体比例、动画、按钮位置和浏览器前进后退行为。

## 3. F1 确认后冻结的实施规范

1. **旧页面是视觉事实源。** 以迁移前 Git 提交中的 HTML、CSS、JS 和真实资产为准，不根据文字描述重新设计，也不把其他页面的新版组件样式强行套入。
2. **先列结构再写代码。** 每页先记录标题、区块顺序、容器宽度、响应式断点、固定区域、交互和全部状态；遗漏一个旧区块也不能进入视觉验收。
3. **CSS 数值优先原样迁移。** 色值、字号、行高、间距、圆角、边框、阴影、比例、断点和层级应沿用旧值；只有冲突、安全或明显浏览器缺陷才允许调整并记账。
4. **Vue 化不等于重做 UI。** 数据获取、类型校验、路由、生命周期和事件改为 Vue；不得复制旧全局脚本、字符串拼 HTML、内联事件或客户端鉴权，但最终 DOM 结构与视觉必须等价。
5. **当前关闭态按真实开关验收。** 视觉基线必须使用首发当前配置。关闭的在线支付、退役能力和虚假承诺不为截图临时开启；前端入口与服务端拒绝必须一致。
6. **无运行时双轨。** 旧文件只从固定 Git 提交生成测试基线，不恢复为可部署页面。新页确认后继续以 Vue 为唯一正式实现。
7. **视觉测试必须能发现“存在但不可见”。** 不能只断言 DOM 数量；正常态需保存全页截图，关键桌面基线尽量使用字节级断言，移动端记录像素差异并人工复查。
8. **状态与交互同样属于一比一。** 正常、加载、空、错误、媒体失败、筛选/选择、悬停/播放、移动固定区域、刷新、前进后退和深链接都需覆盖。
9. **公共组件改动必须回归所有消费者。** 导航、登录弹窗、页脚等共享组件发生变化后，检查重复挂载、活动状态、移动菜单、滚动锁定和既有页面 E2E。
10. **负责人确认是阶段门。** 自动测试通过后状态只能是“待确认”；负责人明确认可后才记录完成并进入下一页。
11. **测试产物不进 Git。** 截图保存在被忽略的 `test-results/`，仓库只提交可重现测试、差异记录和代码。
12. **每页一个可回退提交。** 提交只包含该页及必要共享改动；提交前必须工作树检查、`diff --check`、lint、类型、构建、单测和双视口 E2E。

## 4. 单页实施流程

1. 固定迁移前 Git 提交，读取旧 HTML、CSS、JS 和依赖资产。
2. 使用固定 DTO、桌面 1440×900 和手机 390×844 生成旧版全页截图。
3. 建立视觉清单和交互清单，区分“必须保留”“因退役删除”“因安全替换”。
4. 在 Vue 内复刻页面；复用 API、类型、认证和错误基础设施，不复制旧的全局脚本架构。
5. 对相同测试数据生成 Vue 截图，逐项检查布局和状态；自动验证无横向溢出、URL、键盘操作和控制台错误。
6. 负责人查看旧版/新版截图并确认。未确认前不得宣布页面完成，也不得推广模板。
7. 确认后记录差异、测试和删除项，再进入下一页。

## 5. 允许差异

- 明确退役功能不恢复，也不保留隐藏按钮、接口调用或占位入口。
- 虚构评价、虚假销量、假社交链接和未经确认的售后、物流、价格、材质、交期承诺不恢复。
- 旧实现中的 XSS、开放跳转、客户端权限判断、错误 API DTO、永久私有地址等问题必须使用安全实现替代。
- 为无障碍、错误反馈和不同屏幕修复明显缺陷时，视觉变化应尽量小，并在页面记录中逐项说明。

## 6. 验收门禁

- 功能测试通过不等于视觉迁移完成。
- 每页必须保存可重现的旧版基准生成方式，并生成同数据的新旧截图。
- 视觉检查必须覆盖正常、加载、空、错误和媒体失败状态；详情类页面还需覆盖选择、弹窗和移动固定操作区。
- 删除旧业务文件只能发生在 Vue 页面通过自动检查且负责人完成视觉确认之后。Git 历史仅用于追溯，不作为运行时双轨方案。
