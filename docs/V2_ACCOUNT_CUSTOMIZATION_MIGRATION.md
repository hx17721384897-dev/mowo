# V2 用户账户与私人定制 Vue 迁移记录

> 状态：2026-09-17 V2-A 可信会话基础已完成自动回归；账户占位页仍需由 V2-B 设置页替换后，V2-A 才正式关闭。

## 1. 阶段目标

V2 将用户登录状态、账户设置、地址、我的动画、我的定制以及私人定制的选款式、筛帧和确认流程迁入 Vue。迁移必须保持现有视觉、交互和业务状态机，不改变已由 B2 验证通过的服务端所有权、幂等、私有文件和动画版本规则。

V2 不迁移购物车、结算、订单、后台联络、后台定制队列或生产履约；这些分别属于 V3、V4 和 V5。私人定制确认完成后只交接到 V3 的现有入口，不在 V2 假装已经完成支付。

## 2. 当前事实

### 2.1 正式用户页面

| 旧页面 | 主要职责 | 当前规模 | 删除条件 |
|---|---|---:|---|
| `settings.html` + `settings.js` | 资料、头像、手机号、密码开关、通知、隐私、地址、设备退出、注销 | 约 38 KiB + 独立脚本 | Vue 设置页及全部危险操作回归通过 |
| `my-addresses.html` | 地址 CRUD 与默认地址 | 约 24 KiB | 设置页地址管理和结算地址选择复用组件通过后删除，不保留独立入口 |
| `my-animations.html` | 动画资产、重命名、复购、修改版本、软删除 | 约 23 KiB | 双账号隔离、V1/V2 和复购回归通过 |
| `my-customizations.html` | 定制列表、状态、时间线、人工筛帧确认入口 | 约 11 KiB | 状态映射、详情和移动端回归通过 |
| `customize-start.html` | 机型/SKU、复用动画入口 | 约 52 KiB | 新旧视觉、深链接和资产复用通过 |
| `customize-editor.html` | 自己筛帧、用户确认、动画改版、后台筛帧、后台帧图制作 | 约 110 KiB | 见 2.3，共享消费者全部完成迁移后才能删除 |
| `customize-confirm.html` | SKU 选择、草稿/人工结果确认、进入购物车 | 约 68 KiB | 两类定制与动画复购交接均通过 |

这些页面合计超过 320 KiB，不能以单页大组件方式照搬，也不能重新设计。每页都必须先固定旧版事实源、列出状态和接口，再按原 DOM/CSS 进行等价迁移。

### 2.2 Vue 当前能力与缺口

- 已有统一 `apiRequest`，负责超时、JSON 包装、Access Token、HttpOnly Refresh Cookie 刷新和 401 后单次重试。
- 已有 Pinia `session`，但目前只从 Local Storage 恢复缓存；尚无应用启动时的 `/api/v1/account/me` 可信会话校准，也没有账户路由守卫。
- `AuthDialog` 已接入新版短信登录/注册，但文案固定为“返回商品”，没有通用的受保护路由回跳意图；V2 必须先修正，不能在每个账户页面复制登录逻辑。
- `/account` 仍是占位路由。`AccountLayout` 已能渲染子路由，但没有正式账户导航、加载态、未登录态和会话失效处理。
- 旧用户页仍大量直接读取 `mowo_token` 并自行 `fetch`。迁移后必须统一通过平台 API 客户端，旧请求实现随旧页一起删除。

### 2.3 `customize-editor` 的共享消费者

旧编辑器不只是用户页面，还被以下现行流程调用：

- 用户自己筛帧；
- 用户只读确认工作人员筛帧；
- 用户修改私人动画并保存 V2/V3；
- 负责人/生产人员处理人工筛帧任务；
- 后台帧图制作草稿与负责人入库确认。

因此 V2 不能在只迁移用户路径后直接删除旧编辑器。正确处理方式是先把编辑器核心状态、媒体处理和帧操作拆成一套 Vue 共享能力，再让用户模式与后续后台模式使用明确适配层。V2 完成用户模式后，旧编辑器只允许保留尚未迁移的内部消费者，并登记删除责任到 V4/V5；不得同时保留两套用户筛帧实现。

## 3. 已确认的产品边界

1. 首发不保留独立“我的地址”管理页。设置页承担地址新增、编辑、删除和默认地址等完整管理；V3 下单选地址只提供选择已有地址和新增地址。两处必须复用同一地址领域组件及请求层，通过 `manage` / `select` 模式控制可用操作，不能复制两套 CRUD；设置页迁移验证通过后物理删除 `my-addresses.html`。
2. “哞屋认证”展示按既有决定保留为账户状态信息，但不得恢复已删除的创作者认证申请、自助主页、收益或牛量入口。
3. 密码登录当前由功能配置关闭。Vue 设置页可以展示服务端返回的密码能力状态，但不能擅自开放密码登录。

## 4. V2-A 实施记录

2026-09-17 已完成以下基础能力：

- Pinia 会话不再以 Local Storage 中存在 token 作为已登录依据；有缓存 token 时必须通过 `/api/v1/account/me` 校准，成功后才进入 `authenticated`。
- 缓存用户经过字段白名单解析；损坏或不具备有效 `id` 的缓存会被清除。服务端可信资料会覆盖旧缓存。
- 区分 `anonymous` 与 `unavailable`：401/404 及刷新失败清除本地会话；网络失败不冒充退出，也不使用缓存身份放行受保护路由。
- API 客户端清除失效会话时会通知 Pinia，同一页面内不会继续显示伪登录状态。
- `/account` 已启用统一路由守卫。未登录访问会打开共享登录弹窗，并保存站内回跳路径；回跳拒绝协议地址、协议相对地址、反斜线和控制字符，避免开放重定向。
- 登录/注册弹窗已改为通用“登录并继续”语义，不再固定声称“返回商品”。
- 已建立当前设备退出和全部设备退出的统一 API 调用，但正式 UI 与危险操作恢复由 V2-B 设置页完成。
- 安全复查发现并修正旧请求判定：Access Token 恰好过期时，受鉴权的退出接口现在会先用 HttpOnly Refresh Cookie 更新一次再执行撤销；短信登录/注册等显式禁用重试的接口仍不会触发刷新。否则前端虽然显示退出，服务端 Refresh 会话可能仍有效。

自动门禁结果：ESLint、Prettier、严格类型检查、17 项单元测试、生产构建与部署检查通过；Playwright 桌面/移动 40 项通过，20 项需显式开启的视觉专项按默认配置跳过。新增回归覆盖缓存身份被服务端替换、Access/Refresh 均失效时清理、网络不可用时拒绝信任缓存、未登录路由拦截和可信账号放行。

### V2-B 地址基础进度（尚未接管页面）

2026-09-17 已完成设置页与独立地址页的实现对比：两处均为 `/api/addresses` CRUD、设默认、三级地区和智能识别，没有需要保留的独立页专属业务能力。服务端地址路由已复查，统一执行设备会话/账号状态鉴权，列表按 `userId` 查询，更新、删除和设默认在事务前再次核对资源所有者。

已建立唯一地址领域层：

- `AddressBook.vue` 提供 `manage` / `select` 两种显式模式；管理模式支持增删改和设默认，选择模式只支持选择与新增。
- `AddressEditorDialog.vue`、地址 API、字段白名单、校验、手机脱敏和智能识别只维护一份；结算阶段不得复制实现。
- `regions.json` 从旧版事实源逐字节复制并保留哈希一致，迁移期间不擅自修改行政区数据。
- 旧页面同版本 CropperJS `1.6.2` 已锁定为本地依赖，为后续头像裁剪去除 CDN 依赖。

当前门禁为 22 项单元测试、Lint、严格类型检查和生产构建通过。地址组件尚未挂入 `/account/settings`，没有宣称视觉验收完成；在设置页四个分区、危险操作、桌面/移动视觉和真实接口回归完成前，`settings.html`、`settings.js` 与 `my-addresses.html` 均不得删除。

## 5. 分阶段执行计划

### V2-0：证据冻结与契约矩阵

- 固定七个旧页面的桌面/移动事实源、查询参数、Local/Session Storage 键和所有跳转。
- 为账户、地址、动画、定制申请、上传与机型接口建立请求/响应 DTO 白名单。
- 记录每个旧页面的所有状态、空态、错误态、确认弹窗和危险操作。
- 对账号 A/B、匿名、会话过期和岗位账号建立正反路径矩阵。

### V2-A：可信会话与账户壳（进行中）

- 启动时用 `/api/v1/account/me` 校准缓存用户；缓存只用于首屏占位，不作为授权事实。
- 建立统一受保护路由守卫、登录后安全回跳、退出当前设备/全部设备和会话失效处理。
- 把 `AuthDialog` 改为通用上下文文案，不再固定“返回商品”。
- 建立账户布局与导航，但不创建无业务能力的占位页面。

前三项已完成；最后一项必须与 V2-B 的旧设置页等价迁移一起完成。当前 `/account` 内部占位只用于自动验证可信路由，不作为已交付业务页面，也不得作为视觉设计依据。

### V2-B：设置与地址

- 迁移资料、头像、手机号换绑、通知、隐私、设备和注销。
- 危险操作保留分步验证、服务端阻断原因、重复提交锁和明确失败恢复。
- 地址组件按产品决定被设置页和/或独立地址路由复用，不维护两套 CRUD。
- 人工视觉确认后删除对应旧页面和脚本。

### V2-C：我的动画与我的定制

- 迁移动画资产/草稿分层、重命名、复购、软删除和不可变版本展示。
- 迁移定制列表、筛选、时间线、人工结果确认入口和状态文案。
- 双账号验证所有 ID 深链接；私有文件只使用服务端签发的短期地址。

### V2-D：选款式与编辑器核心

- 先迁移 `customize-start`，保持机型轮播、详情、SKU 和动画复用深链接一比一。
- 抽取单一编辑器核心，覆盖媒体载入、裁剪、抽帧、去重、克隆、排序、撤销、播放和速度预览。
- 用模式权限明确控制“自己筛帧、只读确认、动画改版、后台处理”，禁止只靠隐藏按钮隔离能力。

### V2-E：确认与端到端闭环

- 迁移 `customize-confirm`，区分自己筛帧草稿、人工筛帧结果和动画复购。
- 保留 `DRAFT → CONFIRMED`、`OPTIONS_READY → FRAME_ACCEPTED → CONFIRMED` 等现有服务端状态机。
- 成功后交接现有 V3 购物车入口；不得在 V2 创建第二套订单或支付状态。
- 覆盖刷新、返回、浏览器存储已满、网络中断和重复提交。

### V2-F：逐页删除与阶段关闭

- 每个页面遵循“自动回归通过 → 负责人视觉确认 → 旧代码物理删除 → 引用扫描 → 再回归”。
- 对仍被 V4/V5 使用的编辑器内部模式建立明确临时边界、唯一删除责任和检查脚本；用户模式不得继续可达旧页。
- 更新 302、运行时链接、文档和 B7；确认工作树无旧用户入口、无重复请求客户端、无敏感数据日志。

## 6. 安全与质量门禁

- 前端路由守卫只改善体验，后端身份和对象所有权仍是最终授权边界。
- 不在 URL、日志、错误、Local Storage 或 Pinia 持久状态中保存签名文件地址、短信动作凭据、上传会话或注销验证码。
- 上传二进制到签名地址时不携带 Cookie/Authorization；完成确认地址执行同源/路径白名单。
- 用户 A 无法通过修改 ID 读取或操作用户 B 的地址、动画、定制、草稿或文件。
- 账号注销、手机号换绑、动画删除、草稿提交等操作必须有后端幂等/状态保护，不能只禁用按钮。
- 每个页面必须通过 1440×900 和 390×844 视觉/交互回归，不允许重新设计替代等价迁移。

## 7. 当前结论

V2 的后端业务基线已经由 B2 专项验证，可信会话和账户守卫现已具备自动回归。下一步按 V2-B 冻结 `settings.html`、`settings.js` 和 `my-addresses.html` 的视觉与状态事实源，再以设置页为唯一完整地址管理入口完成等价迁移；不能先重写编辑器或一次性删除旧页面。
