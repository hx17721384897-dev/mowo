# ACCOUNT_DELETION_POLICY.md - 账号注销与资料删除

> 调研日期：2026-08-11，实施更新：2026-08-18
> 项目现状：尚未正式上线，没有真实用户，因此可以直接统一注销规则，不需要为已发布旧客户端保留长期兼容。

## 外部规则与行业做法

以下资料用于理解通行原则，不替代正式法律意见：

- 《个人信息保护法》第四十七条要求在处理目的不再必要、停止服务、用户撤回同意等情形删除个人信息；依法必须保存或技术上难以删除时，只能继续存储并采取安全保护，不得继续日常处理。[工信部法规原文](https://www.miit.gov.cn/zwgk/zcwj/flfg/art/2022/art_04a0f1fb5df244e39688fd5372623a8d.html)
- 《移动智能终端及应用软件用户个人信息保护实施指南 第9部分：注销账户》允许设置冷静期，并要求明确冷静期内登录后的处理方式。[标准 PDF](https://taf.org.cn/upload/AssociationStandard/TTAF%20085-2021%20%E7%A7%BB%E5%8A%A8%E6%99%BA%E8%83%BD%E7%BB%88%E7%AB%AF%E5%8F%8A%E5%BA%94%E7%94%A8%E8%BD%AF%E4%BB%B6%E7%94%A8%E6%88%B7%E4%B8%AA%E4%BA%BA%E4%BF%A1%E6%81%AF%E4%BF%9D%E6%8A%A4%E5%AE%9E%E6%96%BD%E6%8C%87%E5%8D%97%20%E7%AC%AC9%E9%83%A8%E5%88%86%EF%BC%9A%E6%B3%A8%E9%94%80%E8%B4%A6%E6%88%B7.pdf)
- 抖音在注销前验证身份和安全状态，注销后删除或匿名化；依法需要保留的交易信息例外。[抖音隐私政策](https://www.douyin.com/privacy/)
- bilibili 注销协议要求先妥善处理账号服务和财产权益；争议、投诉、诉讼或监管调查期间可以终止注销；网络日志和交易记录按法律期限保留。[bilibili 注销协议](https://game.bilibili.com/sdkyhxy/zxxy/h5/)
- 淘宝、京东、拼多多等主流平台普遍以“身份安全、交易和争议结清、资产处理、提交后审核”为核心，而不是统一采用 7 天冷静期。京东公开规则中的 48 小时属于审核或处理时限，不应直接等同于机器必须等待 48 小时后才能清理。

这些做法的共同点不是某个固定冷静期天数，而是：身份确认、责任结清、明确后果、可追踪处理、删除或匿名化、法定数据隔离保留。

## 已采用的哞屋规则

### 1. 申请前检查

用户必须完成短信二次验证，并且不存在以下未结事项：

- 未完成或售后中的定制/联名订单。
- 仍在销售、暂停销售或有未履约库存的联名作品。
- 待结算、可提现、提现处理中或被冻结的创作者资金。
- 未释放储备金、赔付、违约或争议。
- 生效中的商务合同或需要人工处理的版权争议。
- 正在处理的投诉、监管调查或司法争议。

系统应一次返回全部阻止原因和处理入口，不让用户逐个试错。

### 2. 10 分钟防误操作保护期

- 申请成功后状态变为 `PENDING_DELETE`，记录申请时间，并给予 10 分钟防误操作保护期。
- 立即撤销全部 Refresh Token，旧 Access Token 也必须被统一状态检查阻止。
- 保护期内允许重新登录查看注销状态和已有订单，并主动撤销注销；登录本身不自动撤销。
- 若用户在申请后产生必须处理的既有订单或争议，执行任务会停止注销、恢复账号为正常状态并记录阻断原因。
- 登录本身不自动撤销注销，必须由用户点击“撤销注销”并再次确认，避免误操作。
- 申请后禁止新下单、新联名申请、新合同、新提现、修改资料和新增上传等操作；只放行查询、保护期内撤销、退出及已有订单的收货/取消/售后。

### 3. 自动执行、失败重试和人工关注

- 后台任务默认每 1 分钟扫描一次；保护期满后执行前再次完整检查，出现新争议或未结责任时将申请标为 `BLOCKED`、账号恢复 `ACTIVE` 并写审计记录。
- 满足条件后，将手机号、昵称、头像、生日、个人简介、社交链接等直接身份信息删除或不可逆匿名化。
- 删除未发布草稿、临时上传、简历和未形成合作关系的联络附件。
- 依法需保留的订单、支付、发票、售后、结算、合同、生产和安全日志与用户身份解耦或限制访问，只用于法定义务、争议处理和审计。
- 撤销全部会话，释放手机号唯一键，写不可篡改的注销执行审计记录。
- 文件或数据库清理失败时申请标为 `FAILED`，保留错误摘要并在 15 分钟后重试；连续失败 3 次或首次失败持续超过 1 小时，转为 `MANUAL_REVIEW` 并停止自动重试。
- 异常任务超过 24 小时在后台显示为紧急，48 小时是内部异常处理目标，不是正常注销等待期。清理真正完成前不得把账号标成 `DELETED`。
- 运营客服只能查看脱敏任务状态；负责人可以重试异常任务，或因争议、依法保全等必要原因填写理由后暂停/恢复。暂停时必须分别填写仅工作人员可见的内部原因和给用户看的说明，内部风险、法律或工作人员备注不得原样公开。系统不设置人工“批准注销”“拒绝注销”或“强制删除”按钮。
- 暂停不等于封禁，也不自动取消用户的反悔权。若 `processingStartedAt` 为空，说明尚未开始清理，用户在 `REQUESTED` 或 `PAUSED` 状态均可撤销；若该时间已写入，说明至少一次清理已启动，为避免部分资料已删除造成不一致，用户不能自行撤销，应按公开说明联系工作人员。

### 4. 注销后的公开内容

普通社区文章随账号删除；用户在其他文章下的评论改成“已删除”，点赞、收藏和关注关系删除。未发布作品和草稿停止展示并删除其非必要素材。已签署联名合同、已有消费者购买或仍承担售后义务的作品及生产资料保留，但账号资料匿名化；具体公开展示名称和合同期限仍在联名模块整改时确认。

## 代码实现（2026-08-13）

- 用户接口：`content-service/src/routes/account.js`，包含检查、发送验证码、申请和撤销。
- 统一账号限制：`content-service/src/plugins/jwt.js`，每次鉴权同时核对设备会话和数据库最新账号状态。
- 删除规则和重试：`content-service/src/lib/account-deletion.js`。
- 到期扫描：`content-service/src/lib/scheduler.js`。
- 状态记录：`account_deletion_requests`；状态为 `REQUESTED / PROCESSING / BLOCKED / FAILED / MANUAL_REVIEW / PAUSED / CANCELLED / COMPLETED`。
- 后台任务页：`frontend/pages/admin-account-deletions.html`；客服只读，负责人可重试、暂停和恢复。
- 旧 `/api/v1/user/account/deactivate` 立即注销接口固定返回 `410`，防止两套规则并存。
- 自动检查：在 `content-service` 运行 `npm run check:account-deletion`。

### 本地人工验收工具

- 新增普通测试账号：`npm run test-user:create -- 18800000001 注销测试1`。
- 查看账号和注销任务状态：`npm run test-user:inspect -- 创建时显示的账号ID`。最终注销后手机号已被清除，必须使用账号 ID 查询，不能再次用该手机号登录验证，否则会按新用户重新注册。
- 将已提交的测试注销申请调整为到期：`npm run test-deletion:make-due -- 18800000001`。该命令在生产环境拒绝执行，也不会绕过正式阻断检查；后端任务通常会在 1 分钟内按真实规则处理。
- 本地 `SMS_MOCK=true` 时验证码为 `123456`。测试手机号只用于本地数据库，不会真的发送短信。

2026-08-13 人工验收修正：申请成功后服务端会立即撤销全部设备，因此页面也必须清除已失效的本地 Token。用户点击“撤销注销”时若尚未重新登录，设置页直接打开公共登录弹窗；手机号验证成功后自动继续这次撤销请求。项目没有独立 `auth.html`，路由不得再指向该占位路径。设置页与首页同在 `frontend/pages`，返回首页使用同目录 `index.html`，不能使用 `../index.html`。

2026-08-13 登录/注册边界修正：撤销注销要求原账号重新进行短信身份验证是正常安全流程，但登录入口不得因手机号不存在而自动转为注册。验证码发送和验证均区分 `LOGIN / REGISTER`；登录未知手机号提示前往注册，注册已有手机号提示直接登录，只有正式注册才要求同意协议。

2026-08-13 暂停规则修正：暂停任务改为以“清理是否已经开始”判断撤销权，而不是仅按 `PAUSED` 状态一律禁止；新增独立用户说明并禁止用户接口返回内部原因。自动测试已覆盖清理前暂停可撤销、清理后暂停不可撤销、公开说明可见和内部原因不泄露。当前本地阶段在账号设置页展示说明，真实暂停/恢复短信待短信服务恢复后接入。

## 数据处置矩阵

| 数据 | 最终处理 | 原因 |
|---|---|---|
| 手机号、密码、微信标识、昵称、头像、简介、生日、邮箱、社交链接 | 删除或匿名化 | 注销后不再需要识别用户 |
| 地址、购物车、待付款预订单、未下单定制草稿 | 删除 | 尚未形成必须保留的交易 |
| 社区文章、点赞、收藏、关注 | 删除 | 首发不承担继续公开的必要性 |
| 用户在他人文章下的评论 | 内容匿名化为“已删除” | 保持讨论结构，不继续显示个人身份 |
| 联络表单、认证申请 | 去除姓名、联系方式、IP、设备信息及非必要附件 | 保留最低限度处理记录 |
| 已完成订单、售后、结算、合同、安全审计 | 保留并限制访问 | 履约、争议、财务和法定义务 |
| 订单、售后、合同、联名帧包绑定的私有文件 | 保留但解除普通账号所有权 | 生产、履约和争议仍可能需要 |
| 头像、孤立上传、未形成交易的定制素材 | 删除实际文件，数据库保留删除状态 | 用户隐私和文件删除可追踪性 |

## 后续仍需讨论

1. 已发布联名作品在有历史订单、库存或合同的情况下保留多久、显示什么作者名称。
2. 创作者可下载的数据范围，以及注销前导出功能是否首期就提供。
3. 正式生产环境应把注销任务移到独立 Worker 或可靠任务队列，并把 `MANUAL_REVIEW`、超过 24 小时和超过 48 小时接入站外告警；当前管理页面本身不等于主动告警。
4. 当前保留交易资料，但各类订单、合同、安全日志的精确保存年限仍需法律和财务人员确认。

## 已确认产品决策

截至 2026-08-13，项目负责人先将原 7 天方案调整为 48 小时处理设想，随后进一步确认：正常机器任务不应无理由等待 48 小时，现行规则改为 10 分钟防误操作保护期，期满自动删除或匿名化；失败 15 分钟后重试，连续 3 次失败或持续 1 小时转人工关注，24 小时升级紧急，48 小时作为异常处理目标。责任结清、限制新增业务、交易资料受控保留等总体方案不变；联名历史展示、精确保留期限和数据导出范围留待对应功能整改时继续确认。
