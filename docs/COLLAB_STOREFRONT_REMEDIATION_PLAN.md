# 联名商品货架整改方案

> 制定日期：2026-09-04。
>
> 本文规定 `showcase.html` 联名商品列表、唯一商品详情、后台销售配置、公开接口和购物车衔接的整改步骤。实施时保留现有页面视觉语言和瀑布流，不以旧业务代码为产品依据，也不允许新旧两套详情或购物逻辑并存。

## 1. 首版定位

联名区是一个正式商品货架，不是帖子社区。

- 每张卡片都是可购买的联名商品，不混入文章或普通帖子。
- 列表负责让顾客快速看到动画效果、商品外观和基础购买信息。
- 详情页负责展示作品介绍、完整商品规格、价格、交期、包装内容和购买操作。
- 评论、点赞、关注、收藏、粉丝数等社区能力首版不做。
- 未来若开放社区，重新按照内容审核、举报、隐私、通知和运营规则设计，不保留当前联名页的旧社区代码等待复活。

## 2. 已确认决策

1. 保留瀑布流。动画和产品素材的长宽比例不同，不强行裁成等高方卡。
2. 保留当前哞屋视觉风格、颜色、字体和整体页面气质，只调整信息层级和功能，不无理由重做 UI。
3. 列表卡片同时表达“动画作品”和“可购买商品”，但详细介绍和产品细则留在详情页。
4. 列表、详情、价格、SKU、浏览量、库存/交期都使用正式接口，不继续使用占位数据。
5. 热门排序按浏览量，不按点赞量。
6. SKU 必须展示完整规格；联名作品允许销售哪些 SKU，由后台明确配置。
7. 未登录用户可以选择 SKU 和数量；点击加入购物车或立即购买时登录，登录成功后自动继续原操作。
8. 公开详情接口只能返回顾客需要的数据，内部下架原因、分成、审批人员等信息不得暴露。
9. 旧表达、失效查询参数、演示商品和虚假承诺全部清理。
10. 最终只能保留一套列表、一套详情、一套购物车入口和一套服务端价格规则。

## 3. 顾客视角的信息需求

顾客在联名货架主要解决四个问题：

1. 这个动画是什么效果？
2. 它能做成哪些真实商品？
3. 我选的完整规格多少钱，什么时候发货？
4. 收到什么、如何组装、出现问题如何处理？

与这四个问题无关、又需要额外治理成本的互动信息不进入首版。

## 4. 列表页目标

### 4.1 页面结构

保留：

- 当前页面标题和轻量说明。
- 搜索。
- 瀑布流。
- 骨架加载、空状态、加载失败和继续加载。
- 创作者合作入口，但缩短文案，避免抢占商品浏览主流程。

调整：

- 所有筛选和排序使用服务端查询，不一次加载 200 件后在浏览器处理。
- 页面按真实分页追加商品。
- 创作者数量增加后不再生成无限横向标签；首版可使用创作者筛选菜单或搜索。
- “热门”按有效浏览量排序。
- 默认排序建议为后台推荐顺序，其次提供最新和热门。

### 4.2 卡片信息

每张卡片展示：

- 商品封面。
- 动画轻量预览。
- 联名作品名称。
- 创作者署名。
- 最低成交价，例如“¥199 起”。
- 可选尺寸或简要 SKU 范围。
- 必要的销售状态，如“可购买”“新品”；不能使用虚假热销标签。

卡片不展示：

- 评论、点赞、关注和粉丝数。
- 虚构销量、评分和评价。
- 完整商品参数和长篇作品介绍。
- 容易被误解为“直接加入购物车”的假购物袋按钮。

整张卡片点击后进入唯一详情页。点击创作者署名时，首版推荐回到同一货架并筛选该创作者的联名商品，不进入仍包含文章和关注逻辑的旧创作者社区页。

### 4.3 动画预览

当前鼠标悬停会重新请求详情和全部帧图，访问量增加后成本过高。目标方案：

- 列表接口直接返回轻量预览地址，例如已生成的 `hoverGifUrl` 或专用预览文件。
- 桌面端悬停播放，移开恢复封面。
- 触屏设备不依赖悬停，点击卡片进入详情播放。
- 列表绝不为了悬停返回原始帧图或内部动画资产信息。
- 预览缺失时只显示封面，不阻断购买。

## 5. 唯一详情页目标

### 5.1 文件收口

目标页面命名为 `showcase-detail.html`：

- 迁入现有详情中确认保留的动画播放器、媒体轮播、移动端规格抽屉和粘性购买栏。
- 更新全部入口后删除 `showcase-confirm.html` 和 `showcase-confirm-v2.html` 的业务实现。
- 项目当前没有真实用户和外部旧链接，不需要长期保留两套兼容页面。
- 删除前全项目检索引用，验收结果必须为零处旧详情链接。

### 5.2 第一屏

左侧或上方：

- 动画播放器。
- 商品实拍或 SKU 示例图。
- 图片/动画切换。

右侧或下方：

- 联名作品名称。
- 创作者署名。
- 简短作品介绍。
- 当前选择 SKU 的最终价格。
- 完整 SKU 选项。
- 数量 1 至 10。
- 预计发货时间。
- 加入购物车。
- 立即购买。
- 次要入口“定制我的动画”。

### 5.3 SKU 展示

真实 SKU 至少包含：

- 款式/结构。
- 尺寸。
- 材质。
- 帧数。
- 颜色。
- SKU 图片。
- 最终价格。
- 是否可售和预计交期。

首发 SKU 数量有限，优先使用“完整规格选项卡”，例如：

`标准款 · 5×5cm · 椴木板 · 12帧 · 原色 · ¥199`

这样比让顾客分别组合尺寸、材质、帧数和颜色更不容易产生不存在的组合。以后 SKU 大量增加时，再升级为分层选择器。

### 5.4 详情内容

保留或改为真实数据：

- 作品与创作者介绍。
- 机械动画的实际播放效果。
- 商品尺寸、材质、帧数和颜色。
- 包装内容。
- 是否需要组装、预计组装时间和适用年龄。
- 使用说明和注意事项。
- 预计发货时间。
- 售后政策链接。
- 其他真实联名商品推荐。
- 分享链接；分享不依赖社区互动，可以保留。

删除：

- 静态 4.9 分、256 条评价、1.2k+ 销量。
- 演示评论和评价标签。
- 点赞、关注、粉丝数及其请求代码。
- 没有经过业务确认的“7 天无理由”“满 99 免运费”“快速发货”等承诺。
- 与所选 SKU 不一致的固定材质、年龄、包装清单和产品细节占位符。
- 没有实际数据来源的“热销款”标签。

## 6. 后台联名商品工作区

规划时 `CollabWork.supportedSkus` 虽然存在，但缺少一套清楚的商品编辑和上架工作区。2026-09-05 已将原来的窄销售弹窗退役：`admin-collab-works.html` 仍是联名商品总入口，点击“编辑商品”进入 `admin-collab-product-edit.html` 完成整件商品的配置。两页属于同一个联名管理体系，没有第二套并行商品系统；正式销售数据见本文件第 13 节第 2 步实施记录。

### 6.1 管理员操作

负责人或合作运营可以：

1. 查看该联名动画的核心帧数和资产版本。
2. 从 `admin-models.html` 已建立且启用的真实 SKU 中选择允许销售的 SKU。
3. 每个候选 SKU 显示图片、款式、尺寸、材质、帧数、颜色、编码和基础价。
4. 系统自动排除帧数不兼容或停用 SKU。
5. 为所选 SKU 配置联名最终售价；首发不向顾客展示基础价与创作者加价拆分。
6. 设置该 SKU 是仅现货还是允许现做，以及预计发货天数。
7. 设置商品推荐顺序、新品标记和公开展示文案。
8. 预览顾客端列表卡片和详情规格。
9. 保存后留下员工操作记录。

### 6.2 上架门槛

作品只有同时满足以下条件才能公开销售：

- 联名审核通过。
- 明确标记上架。
- `shelfStatus=on_sale`。
- 不是修改过程中的影子记录。
- 已关联有效 `ANM + Vn`。
- 至少配置一个启用、兼容且有最终售价的 SKU。
- 封面和动画预览可读取。
- 预计交期已有有效配置。

缺少任一项时，后台展示具体阻断原因，不能出现“后台显示上架但顾客无法购买”。

### 6.3 成熟电商后台对照（2026-09-05）

本节用于吸收成熟平台的通用做法，不表示照搬淘宝或把首版做成大型商家平台。

- 淘宝把商品信息完整性拆为库存、价格、SKU、描述和上下架等独立能力；商品只有上架后才可被顾客访问，下架后仍留在后台“仓库中”。淘宝也明确 SKU 是最小库存单位，并允许用商家商品/规格编码与外部系统做稳定映射。来源：[淘宝开放平台《商品信息获取和修改》](https://developer.alibaba.com/docs/doc.htm?articleId=122&docType=1&treeId=1)。
- 淘宝发布数据还包含标题、类目属性、图片、数量、价格、运费承担/运费模板、推荐和计划上架时间；标题、图片、属性、价格、描述和售后信息需要相互一致。来源：[淘宝商品发布接口字段](https://developer.alibaba.com/docs/api.htm?apiId=295)、[淘宝商品管理类目规则](https://developer.alibaba.com/docs/doc.htm?articleId=122125&docType=1&source=search&treeId=253)。
- 抖店把一个 SKU 绑定到独立价格和库存，并在发布前按类目读取允许的发货模式、发货时效、图片和资质规则；其接口还区分现货、预售/阶梯发货、库存预占和运费模板。来源：[抖店商品打通接入指南](https://op.jinritemai.com/docs/api/200/359)、[抖店发布商品接口](https://op.jinritemai.com/docs/api-docs/14/250)。
- Shopify 的商品详情由标题/描述、媒体、价格、库存、物流、规格、购买方式、自定义字段、搜索展示、商品状态和发布渠道构成；商品状态区分草稿、销售中、归档和仅链接可见。来源：[Shopify 产品详情](https://help.shopify.com/en/manual/products/details/product-details-page)。
- Shopify 支持单独发布或停止发布某个规格：父商品未发布时全部规格不可见，父商品发布后也只有被发布的规格可售；停止销售某个规格时可保留历史记录，而不是必须删除。来源：[Shopify 规格发布管理](https://help.shopify.com/en/manual/products/variants/publish-variants)。
- Shopify 的批量编辑器采用“每行一个商品/规格、每列一个属性”，支持集中修改价格、SKU、库存等，并显示修改前后值和冲突警告。这种方式适合 SKU 较多时使用。来源：[Shopify 批量编辑](https://help.shopify.com/zh-CN/manual/shopify-admin/productivity-tools/bulk-editing)、[批量库存编辑](https://help.shopify.com/zh-CN/manual/products/inventory/adjusting-inventory/bulk-editing-inventory)。

对哞屋最重要的结论：

1. `联名商品` 与 `真实 SKU` 必须保持两层结构。一个动画联名商品可以销售多个 SKU；每个 SKU 独立控制价格、交期、供货方式和是否可售。
2. 动画资产 `ANM + Vn`、联名商品和硬件 SKU 是三个不同对象，不能混用编码。后续建议为公开销售商品增加稳定商品编码，不能拿数据库 UUID 或 ANM 编码代替商品编号。
3. 上架不是“审核通过”的同义词。内容/授权审核通过后进入待配置；销售资料检查通过后，运营人员才能明确发布。
4. 商品停售、单个 SKU 停售和永久归档应分开。停售保留历史订单和配置，不能为了隐藏商品而删除记录。
5. 媒体、承诺、售价、交期、库存和售后说明必须互相一致，顾客端只能展示系统真实能够履行的内容。

### 6.4 哞屋目标后台结构

原销售配置弹窗只完成了最小安全底座，现已升级为完整编辑工作区并从正式代码中删除旧弹窗。工作区仍由 `admin-collab-works.html` 进入，共用同一作品、动画资产、SKU、库存和上架状态。

#### A. 商品资料

- 稳定联名商品编码、商品标题、货架短介绍、完整详情说明。
- 列表封面、详情轮播图、动画预览、不同 SKU 对应的示意图。
- 创作者公开署名、授权/合同状态摘要；私密证明只在后台查看，绝不进入公开接口。
- 商品标签、系列、推荐顺序和搜索关键词。标签必须来自后台可维护选项，不能把自由输入直接当作顾客筛选条件。

#### B. 销售规格

- 使用真实 SKU 表格，每行显示图片、SKU 编码、款式、尺寸、材质、帧数、颜色、基础价和当前库存摘要。
- 每行配置最终售价、是否可售、仅现货/允许现做、预计发货天数和排序。
- 支持按尺寸、帧数、材质和状态筛选；支持多选后批量设置售价规则、供货方式和交期。
- 不兼容 SKU 永远不能被选中；停用 SKU 保留历史配置但标记为停售，不从历史订单中删除。
- 价格修改需要显示修改前后值；商品已有未完成订单时，只影响新订单，历史订单继续使用成交快照。

#### C. 库存与履约

- 只展示库存系统的摘要，不在联名页面再维护第二套库存数字。
- “仅现货”读取可售库存，为零时停止该 SKU；“允许现做”可在无成品库存时继续销售并展示真实交期。
- 读取 SKU 已有重量、包装尺寸和材料包关系；尚未确认的数据不伪造默认承诺。
- 后续接入运费模板、限购规则、预计发货区间和销售区域；首版没有真实规则时不展示“包邮”“快速发货”等字样。

#### D. 发布控制

- 状态建议统一为：`待审核 -> 待配置 -> 可上架 -> 销售中 -> 暂停/下架 -> 归档`。修改中的影子版本不能成为第二件公开商品。
- 页面固定显示上架检查清单，并按“素材、授权、规格、价格、库存/现做、交期、顾客说明”分组展示阻断原因。
- 提供“保存草稿”“顾客端预览”“确认上架”三个不同动作；保存资料不能暗中改变公开状态。
- 首版保留人工立即上架。计划上架、多渠道发布和仅链接可见可后续增加，不在当前首版堆入。

#### E. 运营和审计

- 展示最近修改人、修改时间、上架/暂停/下架原因和操作记录。
- 价格、SKU、交期和公开文案的修改保留版本摘要，出现顾客争议时能还原当时页面与成交快照。
- 商品较多后增加批量编辑和批量上下架；批量操作必须先显示受影响商品和阻断项，不能静默跳过失败项。
- 浏览、加购、下单、退款等经营数据放在独立统计区，不把尚未接通的假销量和假评分写入商品资料。

### 6.5 分期建议

**首版必须补齐：**

1. 把销售配置升级为分区工作区，补商品详情文案、媒体管理、SKU 启停、筛选与批量设置。
2. 增加稳定联名商品编码和顾客端预览。
3. 明确“待配置/可上架”状态与分组检查清单。
4. 从库存系统读取每个 SKU 的真实可售摘要，并严格执行仅现货/允许现做。
5. 对价格、SKU、交期、上架和下架保留清楚的变更记录。

**主流程跑通后增加：**

- 运费模板、限购、销售区域、计划上架、批量编辑、商品复制和更完整的搜索标签。
- 经营数据看板、异常库存/交期提醒、多人编辑冲突提示。

**首版暂不做：**

- 平台促销、优惠券、满减、直播渠道、多仓销售和复杂的 SEO 工具。
- 顾客评论、评分、粉丝、点赞及由此产生的审核系统。
- 创作者自行即时改价。旧创作者加价功能需另行确定为“调价申请”或线下合作台账，不能成为公开售价的第二来源。

## 7. 公开接口整改

公开接口采用明确白名单，禁止把数据库整行展开给前端。

### 7.1 列表接口只返回

- 商品 ID。
- 标题和简短介绍。
- 封面与轻量预览。
- 创作者公开昵称和头像。
- 最低最终售价。
- 可选尺寸/规格摘要。
- 新品等公开标记。
- 有效浏览量。
- 预计发货摘要。

支持服务端参数：

- `page`、`limit`。
- `q` 搜索标题或创作者。
- `creatorId`。
- `sort=recommended|latest|views`。

### 7.2 详情接口只返回

- 上述公开信息。
- 作品完整公开介绍。
- 动画播放文件。
- 商品媒体。
- 可售 SKU 的完整公开规格、最终价格、交期和库存展示状态。
- 公共包装/使用/售后说明。

绝不返回：

- `revenueRate`、`creatorMarkups` 原始拆分。
- `approvedBy`、内部审批记录。
- `offShelfReason`、内部备注和给创作者的通知。
- 原始 OSS 对象键、合同、授权文件或生产文件。
- 修改版差异、内部批次、后台库存明细。
- 未上架、暂停、下架或影子修改记录。

详情查询和加入购物车必须使用完全相同的“公开可售”判断函数，避免旧直链绕过列表购买下架商品。

## 8. 浏览量与热门排序

热门按浏览量，但不能让每次刷新无限增加：

- 只有成功打开正式商品详情才计入。
- 同一浏览器/账号在一个时间窗口内重复刷新只计一次。
- 爬虫、健康检查和后台预览不计入。
- 首版使用数据库原子计数和服务端去重即可；访问量增大后改为缓存/队列聚合，避免每次浏览都争用商品表。
- 列表排序读取汇总值，不在列表请求中逐条计算。
- 浏览量是排序依据，首版不必在卡片上公开显示具体数字。

## 9. 登录后继续购物

未登录用户选择 SKU 和数量后点击购买：

1. 浏览器保存短期 `pendingPurchase`，内容仅包括商品 ID、SKU ID、数量和原动作。
2. 打开登录，并携带安全的返回页面。
3. 登录成功后重新向服务器校验商品、SKU、价格、上架状态和数量。
4. 校验通过后自动执行“加入购物车”或“立即购买”。
5. 成功后立即清除 `pendingPurchase`，刷新或再次登录不能重复加入。
6. 价格或状态发生变化时停止自动操作，提示顾客重新确认。

这里保存的是“待执行意图”，不是游客购物车。正式购物车仍只存在服务器中。

## 10. 购物车与价格规则

- 联名成交价只能由服务端统一报价函数计算。
- 详情、购物车、结算、支付和订单快照必须使用同一结果。
- 购物车加入时再次校验作品公开可售和 SKU 属于该联名作品。
- 购物车读取时再次检查下架、停用、价格变化和交期变化。
- 联名款锁定 `ANM + 动画版本 + SKU`，支付后能进入现有生产流程。
- 普通购买数量限制为 1 至 10；合并已有购物车条目后也不能超过 10。
- 无现货但允许现做时不能误报“缺货”，应显示预计交期；仅现货 SKU 才按可售库存阻断。
