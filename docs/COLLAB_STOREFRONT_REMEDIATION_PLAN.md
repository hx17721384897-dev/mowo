# 联名商品货架整改方案

> 制定日期：2026-09-04。
>
> 本文规定 `showcase.html` 联名商品列表、唯一商品详情、后台销售配置、公开接口和购物车衔接的整改步骤。实施时保留现有页面视觉语言和瀑布流，不以旧业务代码为产品依据，也不允许新旧两套详情或购物逻辑并存。

## 1. 首版定位

联名区是一个正式商品货架，不是帖子社区。

- 每张卡片都是可购买的联名商品，不混入文章或普通帖子。
- 列表负责让顾客快速看到动画效果、商品外观和基础购买信息。
- 详情页负责展示作品介绍、完整商品规格、价格、交期、包装内容和购买操作。
- 评论、点赞、关注、收藏、粉丝数等社区能力首版不做。
- 未来若开放社区，重新按照内容审核、举报、隐私、通知和运营规则设计，不保留当前联名页的旧社区代码等待复活。

## 2. 已确认决策

1. 保留瀑布流。动画和产品素材的长宽比例不同，不强行裁成等高方卡。
2. 保留当前哞屋视觉风格、颜色、字体和整体页面气质，只调整信息层级和功能，不无理由重做 UI。
3. 列表卡片同时表达“动画作品”和“可购买商品”，但详细介绍和产品细则留在详情页。
4. 列表、详情、价格、SKU、浏览量、库存/交期都使用正式接口，不继续使用占位数据。
5. 热门排序按浏览量，不按点赞量。
6. SKU 必须展示完整规格；联名作品允许销售哪些 SKU，由后台明确配置。
7. 未登录用户可以选择 SKU 和数量；点击加入购物车或立即购买时登录，登录成功后自动继续原操作。
8. 公开详情接口只能返回顾客需要的数据，内部下架原因、分成、审批人员等信息不得暴露。
9. 旧表达、失效查询参数、演示商品和虚假承诺全部清理。
10. 最终只能保留一套列表、一套详情、一套购物车入口和一套服务端价格规则。

## 3. 顾客视角的信息需求

顾客在联名货架主要解决四个问题：

1. 这个动画是什么效果？
2. 它能做成哪些真实商品？
3. 我选的完整规格多少钱，什么时候发货？
4. 收到什么、如何组装、出现问题如何处理？

与这四个问题无关、又需要额外治理成本的互动信息不进入首版。

## 4. 列表页目标

### 4.1 页面结构

保留：

- 当前页面标题和轻量说明。
- 搜索。
- 瀑布流。
- 骨架加载、空状态、加载失败和继续加载。
- 创作者合作入口，但缩短文案，避免抢占商品浏览主流程。

调整：

- 所有筛选和排序使用服务端查询，不一次加载 200 件后在浏览器处理。
- 页面按真实分页追加商品。
- 创作者数量增加后不再生成无限横向标签；首版可使用创作者筛选菜单或搜索。
- “热门”按有效浏览量排序。
- 默认排序建议为后台推荐顺序，其次提供最新和热门。

### 4.2 卡片信息

每张卡片展示：

- 商品封面。
- 动画轻量预览。
- 联名作品名称。
- 创作者署名。
- 最低成交价，例如“¥199 起”。
- 可选尺寸或简要 SKU 范围。
- 必要的销售状态，如“可购买”“新品”；不能使用虚假热销标签。

卡片不展示：

- 评论、点赞、关注和粉丝数。
- 虚构销量、评分和评价。
- 完整商品参数和长篇作品介绍。
- 容易被误解为“直接加入购物车”的假购物袋按钮。

整张卡片点击后进入唯一详情页。点击创作者署名时，首版推荐回到同一货架并筛选该创作者的联名商品，不进入仍包含文章和关注逻辑的旧创作者社区页。

### 4.3 动画预览

当前鼠标悬停会重新请求详情和全部帧图，访问量增加后成本过高。目标方案：

- 列表接口直接返回轻量预览地址，例如已生成的 `hoverGifUrl` 或专用预览文件。
- 桌面端悬停播放，移开恢复封面。
- 触屏设备不依赖悬停，点击卡片进入详情播放。
- 列表绝不为了悬停返回原始帧图或内部动画资产信息。
- 预览缺失时只显示封面，不阻断购买。

## 5. 唯一详情页目标

### 5.1 文件收口

目标页面命名为 `showcase-detail.html`：

- 迁入现有详情中确认保留的动画播放器、媒体轮播、移动端规格抽屉和粘性购买栏。
- 更新全部入口后删除 `showcase-confirm.html` 和 `showcase-confirm-v2.html` 的业务实现。
- 项目当前没有真实用户和外部旧链接，不需要长期保留两套兼容页面。
- 删除前全项目检索引用，验收结果必须为零处旧详情链接。

### 5.2 第一屏

左侧或上方：

- 动画播放器。
- 商品实拍或 SKU 示例图。
- 图片/动画切换。

右侧或下方：

- 联名作品名称。
- 创作者署名。
- 简短作品介绍。
- 当前选择 SKU 的最终价格。
- 完整 SKU 选项。
- 数量 1 至 10。
- 预计发货时间。
- 加入购物车。
- 立即购买。
- 次要入口“定制我的动画”。

### 5.3 SKU 展示

真实 SKU 至少包含：

- 款式/结构。
- 尺寸。
- 材质。
- 帧数。
- 颜色。
- SKU 图片。
- 最终价格。
- 是否可售和预计交期。

首发 SKU 数量有限，优先使用“完整规格选项卡”，例如：

`标准款 · 5×5cm · 椴木板 · 12帧 · 原色 · ¥199`

这样比让顾客分别组合尺寸、材质、帧数和颜色更不容易产生不存在的组合。以后 SKU 大量增加时，再升级为分层选择器。

### 5.4 详情内容

保留或改为真实数据：

- 作品与创作者介绍。
- 机械动画的实际播放效果。
- 商品尺寸、材质、帧数和颜色。
- 包装内容。
- 是否需要组装、预计组装时间和适用年龄。
- 使用说明和注意事项。
- 预计发货时间。
- 售后政策链接。
- 其他真实联名商品推荐。
- 分享链接；分享不依赖社区互动，可以保留。

删除：

- 静态 4.9 分、256 条评价、1.2k+ 销量。
- 演示评论和评价标签。
- 点赞、关注、粉丝数及其请求代码。
- 没有经过业务确认的“7 天无理由”“满 99 免运费”“快速发货”等承诺。
- 与所选 SKU 不一致的固定材质、年龄、包装清单和产品细节占位符。
- 没有实际数据来源的“热销款”标签。

## 6. 后台联名销售配置

当前 `CollabWork.supportedSkus` 虽然存在，但缺少一套清楚的上架后销售配置界面。首版建议在现有 `admin-collab-works.html` 的作品详情中增加“销售配置”，不再新建另一套联名管理系统。

### 6.1 管理员操作

负责人或合作运营可以：

1. 查看该联名动画的核心帧数和资产版本。
2. 从 `admin-models.html` 已建立且启用的真实 SKU 中选择允许销售的 SKU。
3. 每个候选 SKU 显示图片、款式、尺寸、材质、帧数、颜色、编码和基础价。
4. 系统自动排除帧数不兼容或停用 SKU。
5. 为所选 SKU 配置联名最终售价；首发不向顾客展示基础价与创作者加价拆分。
6. 设置该 SKU 是仅现货还是允许现做，以及预计发货天数。
7. 设置商品推荐顺序、新品标记和公开展示文案。
8. 预览顾客端列表卡片和详情规格。
9. 保存后留下员工操作记录。

### 6.2 上架门槛

作品只有同时满足以下条件才能公开销售：

- 联名审核通过。
- 明确标记上架。
- `shelfStatus=on_sale`。
- 不是修改过程中的影子记录。
- 已关联有效 `ANM + Vn`。
- 至少配置一个启用、兼容且有最终售价的 SKU。
- 封面和动画预览可读取。
- 预计交期已有有效配置。

缺少任一项时，后台展示具体阻断原因，不能出现“后台显示上架但顾客无法购买”。

## 7. 公开接口整改

公开接口采用明确白名单，禁止把数据库整行展开给前端。

### 7.1 列表接口只返回

- 商品 ID。
- 标题和简短介绍。
- 封面与轻量预览。
- 创作者公开昵称和头像。
- 最低最终售价。
- 可选尺寸/规格摘要。
- 新品等公开标记。
- 有效浏览量。
- 预计发货摘要。

支持服务端参数：

- `page`、`limit`。
- `q` 搜索标题或创作者。
- `creatorId`。
- `sort=recommended|latest|views`。

### 7.2 详情接口只返回

- 上述公开信息。
- 作品完整公开介绍。
- 动画播放文件。
- 商品媒体。
- 可售 SKU 的完整公开规格、最终价格、交期和库存展示状态。
- 公共包装/使用/售后说明。

绝不返回：

- `revenueRate`、`creatorMarkups` 原始拆分。
- `approvedBy`、内部审批记录。
- `offShelfReason`、内部备注和给创作者的通知。
- 原始 OSS 对象键、合同、授权文件或生产文件。
- 修改版差异、内部批次、后台库存明细。
- 未上架、暂停、下架或影子修改记录。

详情查询和加入购物车必须使用完全相同的“公开可售”判断函数，避免旧直链绕过列表购买下架商品。

## 8. 浏览量与热门排序

热门按浏览量，但不能让每次刷新无限增加：

- 只有成功打开正式商品详情才计入。
- 同一浏览器/账号在一个时间窗口内重复刷新只计一次。
- 爬虫、健康检查和后台预览不计入。
- 首版使用数据库原子计数和服务端去重即可；访问量增大后改为缓存/队列聚合，避免每次浏览都争用商品表。
- 列表排序读取汇总值，不在列表请求中逐条计算。
- 浏览量是排序依据，首版不必在卡片上公开显示具体数字。

## 9. 登录后继续购物

未登录用户选择 SKU 和数量后点击购买：

1. 浏览器保存短期 `pendingPurchase`，内容仅包括商品 ID、SKU ID、数量和原动作。
2. 打开登录，并携带安全的返回页面。
3. 登录成功后重新向服务器校验商品、SKU、价格、上架状态和数量。
4. 校验通过后自动执行“加入购物车”或“立即购买”。
5. 成功后立即清除 `pendingPurchase`，刷新或再次登录不能重复加入。
6. 价格或状态发生变化时停止自动操作，提示顾客重新确认。

这里保存的是“待执行意图”，不是游客购物车。正式购物车仍只存在服务器中。

## 10. 购物车与价格规则

- 联名成交价只能由服务端统一报价函数计算。
- 详情、购物车、结算、支付和订单快照必须使用同一结果。
- 购物车加入时再次校验作品公开可售和 SKU 属于该联名作品。
- 购物车读取时再次检查下架、停用、价格变化和交期变化。
- 联名款锁定 `ANM + 动画版本 + SKU`，支付后能进入现有生产流程。
- 普通购买数量限制为 1 至 10；合并已有购物车条目后也不能超过 10。
- 无现货但允许现做时不能误报“缺货”，应显示预计交期；仅现货 SKU 才按可售库存阻断。

## 11. 相关页面旧表达清理

本批至少核对并修改：

- `index.html`：删除无效的 `?style=classic/mini/retro/diy` 链接，除非后台已有真实对应筛选；演示创意卡不能继续伪装成真实商品。
- `products.html`：“去社区挑选作品”改为“选购联名作品”，产品介绍只引用真实已开放款式。
- `nav.js`：搜索入口进入联名商品搜索可以保留，但名称和行为必须一致。
- `creator-profile.html`：联名卡片不跳入旧文章/关注体系；首版改为货架内按创作者筛选。
- 详情页“更多创意”：使用正式列表接口和唯一详情链接，删除静态占位卡。
- 全项目删除 `showcase-confirm-v2.html` 和旧 `showcase-confirm.html` 的引用。

本批不借机全面重做首页和产品介绍页，只修复与联名购买路线直接冲突或误导顾客的入口和文案。

## 12. 社区旧代码处理边界

从联名正式页面和联名公开接口中删除：

- 点赞按钮、点赞数和点赞请求。
- 关注按钮、粉丝数和关注请求。
- 评论/评价结构、筛选和演示数据。
- 依赖 `community` 功能开关生成上述 UI 的分支。
- 联名专用点赞接口和公开 DTO 中的互动字段。

本批不顺带删除整个项目所有历史社区表和旧归档页面，避免把联名整改扩大成数据库清理；它们继续由首发总开关关闭。未来单独执行“社区历史代码退役”时，再评估迁移或删除全局 `Like/Comment/Follow` 数据模型。重要原则是：**正式联名购买路线不再依赖或携带社区代码。**

## 13. 分步实施顺序

### 第 1 步：公开接口安全和统一可售判断

- 建立公开字段白名单 DTO。
- 统一列表、详情和购物车的上架条件。
- 排除影子修改记录、停用 SKU 和内部字段。
- 建立统一联名最终价计算函数。
- 增加接口反向测试，确认内部字段永不返回。

这是最高优先级。完成前不改页面购买按钮，避免新 UI 继续消费不安全接口。

**实施状态：已于 2026-09-04 完成基础安全收口。**

- 新增 `src/lib/collab-storefront.js`，列表、详情、加入购物车、游客意图合并、购物车复核和结算共同使用一套公开可售判断与最终价计算。
- 当前公开可售条件统一为：审核通过、明确上架、货架状态为销售中、且不是修改影子记录。
- 停用 SKU、停用款式或不属于该联名作品的 SKU 均不能加入购物车；作品后续暂停时，旧购物车条目会失效且不能结算。
- 公开列表和详情改为字段白名单，不再返回分成比例、创作者加价拆分、审批人、内部下架原因、修改记录和互动字段。
- 联名最终价当前统一为 `SKU 基础价 + 该作品对该 SKU 的创作者加价`；列表最低价、详情规格价、购物车快照和结算复核使用同一函数。
- 删除正式联名公开路由中的点赞接口。数据库历史互动模型暂未在本步清理。
- 新增 `npm run check:collab-storefront`，覆盖公开范围、字段泄露、价格一致、错状态加购和下架后结算阻断。

本步尚不代表整个商品货架完成。作品“至少一个完整可售 SKU、动画资产、封面预览和交期”的上架门槛，需要第 2 步后台销售配置落地后才能完整强制执行；分页搜索、浏览量、页面和旧详情删除仍按后续步骤进行。

### 第 2 步：后台销售配置

- 在现有联名作品管理中增加 SKU 选择和最终售价。
- 增加现货/现做、交期、推荐顺序和公开文案。
- 增加上架完整性检查和员工操作记录。

### 第 3 步：列表接口与 `showcase.html`

- 正式分页、搜索、推荐/最新/浏览量排序。
- 卡片接入价格、规格摘要和轻量动画预览。
- 保留瀑布流和现有视觉风格。
- 删除社区卡片操作和客户端一次性加载 200 件的逻辑。

### 第 4 步：唯一详情页

- 建立 `showcase-detail.html`。
- 迁入经过确认的播放器、轮播、移动端抽屉和粘性购买栏。
- 接入完整 SKU、最终价格、交期和真实商品说明。
- 删除静态评价、销量、粉丝、点赞和错误服务承诺。

### 第 5 步：登录后继续操作和购物车

- 建立一次性 `pendingPurchase`。
- 登录后重新校验并自动加入购物车/进入结算。
- 修复数量上限、合并数量、联名价格和在售复核。

### 第 6 步：浏览量和热门

- 增加有效浏览记录/汇总。
- 去重、防刷并排除后台预览。
- 列表热门排序改为浏览量。

### 第 7 步：删除重复与修复相关入口

- 删除两套旧详情业务实现。
- 更新首页、产品页、导航、创作者和推荐入口。
- 全项目检索旧文件名、游客购物车、社区联名代码和演示文案。

### 第 8 步：回归与文档

- 桌面与手机人工验收。
- 上架/下架、错 SKU、价格变化、登录返回、重复点击、数量上限和内部字段泄露自动测试。
- 更新代码事实、验收清单、差异台账和 Git 存档。

## 14. 每一步完成标准

每个步骤都必须同时满足：

1. 新功能可用。
2. 被替代的旧入口和旧业务代码已移除。
3. 页面仍保持当前哞屋视觉风格，桌面和手机无错位。
4. 服务端是权限、价格和上架状态的最终判断者。
5. 对应自动检查或人工步骤已经记录。
6. 对应 Markdown 已更新并单独 Git 存档。

## 15. 第一阶段验收重点

第 1 步完成后，应能够证明：

- 列表只出现真正可售作品。
- 暂停、下架、未完整配置和修改影子作品，直接访问详情也返回不可购买。
- 普通顾客响应中找不到任何分成、内部下架原因、审批人或对象键。
- 详情价格与购物车加入价格使用同一个服务端计算结果。
- 选择不属于该作品的 SKU 会被拒绝。
- 社区关闭与否不再改变联名公开商品 DTO。
