# 材料包款生产批次与并行作业流程

> 确认日期：2026-08-23  
> 当前范围：只设计和实施“帧素材包 + 标准材料包”的材料包款生产线；组装完成款属于另一条产线，本阶段不纳入。  
> 文档性质：本文同时记录已确认业务规则、当前代码差异和分阶段目标。标为“目标”的内容不表示代码已经完成。

## 一、简单说明

一次付款形成一个用户总订单 `SO`。总订单中可以有多种商品和多件实体产品，每件实体产品都有独立生产任务 `PU`。同一总订单首版只允许一个收货地址，因此其中所有生产任务必须全部完成后一起发货。

材料包款由两部分组成：

1. 私人帧素材包：根据订单锁定的动画版本打印、裁切并装入小袋，必须绑定具体 `PU`，不能提前作为公共库存生产。
2. 标准材料包：与动画内容无关，可以提前按 SKU 批量组装入库，使用 `KB` 批次和 `BX` 箱码管理。

生产批次 `PB` 是某次主动选择并冻结的一组完整用户总订单。一天可以创建多个生产批次。创建批次和下载文件必须分开：重复下载同一批次文件不能重复建批次、重复推进状态或重复扣减库存。

## 二、已确认业务规则

1. 当前使用 A4 纸打印，现阶段人工裁切，后续可能改用机器裁切。
2. 5x5cm 十二帧目前一张 A4 打印 12 张；二十四帧使用两张 A4、每张 12 张；十六帧使用一张 A4 打印 16 张。
3. 生产顺序由独立“打印与裁切设置”维护，不能写死在代码里，也不直接复用商品展示排序。当前按打印裁切组、组内帧数规则、款式和支付时间排序；详细规则见 `PRINT_PRODUCTION_PLANNING.md`。
4. 帧素材包标签使用单独标签纸打印并贴在帧包上，不利用帧图纸空白位置混合打印。标签格式和打印时机后续确认，本阶段只预留关联关系。
5. 生产批次创建后，帧图作业和材料领料并行进行；不要求等待帧图裁切完成后才开始寻找材料包。
6. 材料包按“生产批次 + SKU”提前领取并分区暂存，不同 SKU 不得混放。帧包完成后再逐件配对。
7. 一个总订单首版只有一个地址。一个订单内的全部 `PU` 必须作为整体加入同一生产批次，并在全部完成后一起发货。
8. 快递面单与用户总订单绑定。面单可以在生产前准备，最终打包时扫描面单显示该订单应包含的全部产品，全部核对通过后才能发货。
9. 每次主动创建生产批次后，应有独立批次详情页，长期展示批次所含订单、生产件、文件、领料和完成情况。
10. 失败、报废、缺件和重做必须保留追加记录，不能覆盖原生产结果。详细异常流程可以在主生产流程跑通后实施，但数据结构和页面必须预留位置。
11. 首版不为每个普通标准材料包贴单件码；领料通过 SKU、`KB` 批次、`BX` 箱码和数量追踪。帧素材包必须有单件身份，最终配对关系落到 `PU`。

## 三、生产前检查

生产前检查不是重新审核用户内容是否适合制作。内容审核和效果判断应在定制或下单前完成。这里仅检查订单资料是否已经具备生产条件。

### 不能进入生产批次

- 总订单未付款、已取消、处于需要暂停生产的售后状态；
- 总订单没有生产任务，或商品数量与 `PU` 数量不一致；
- 同一总订单中的部分 `PU` 已经进入另一个未完成批次；
- 动画版本、帧图清单或必要文件缺失；
- SKU 不存在、已经停用，或没有可用的生产打印配置；
- 收货信息不完整，或同一总订单的生产件出现不一致地址。

### 可以进入但必须提示

- 标准材料包可用数量少于本批次所需数量；
- 材料包正在补充，预计可以在帧包完成前备齐；
- 其他不影响冻结订单和开始打印、但可能影响最终配对的临时问题。

管理员可以在看见明确缺口后确认继续创建批次。系统必须保存当时的提醒快照，不能只弹一次提示后丢失。

## 四、目标生产流程

```text
已付款且资料完整的总订单
  -> 选择完整 SO 并执行生产前检查
  -> 创建 PB 生产批次并冻结订单、动画版本、SKU 和地址
      -> 帧图线：生成打印任务 -> 打印 -> 裁切 -> 装袋 -> 帧包完成
      -> 领料线：按 SKU 汇总 -> 推荐 KB/BX -> 领取 -> 批次暂存
  -> 两线汇合：帧素材包与标准材料包逐件配对
  -> 按 SO 放入订单周转区
  -> SO 下全部 PU 配齐后进入打包队列
  -> 扫描快递面单并逐件核对
  -> 确认发货
```

帧图线和领料线拥有各自的队列与进度，不使用一条顺序强迫所有岗位等待。生产批次是共同边界，`PU` 是两条线最终配对的共同身份。

## 五、生产批次页面

生产后台需要独立的生产批次列表与详情，不再只依靠订单页的批次下拉框。

### 批次列表

- 批次号、创建时间、创建人和状态；
- 用户总订单数量、单件生产任务数量和 SKU 种类；
- 帧包完成、材料已领、已经配对、整单齐全和异常数量；
- 支持按状态、日期和批次号查找。

### 批次详情

- 批次概览和生产前提醒；
- 完整总订单列表，展开后查看订单商品和所有 `PU`；
- 帧图打印/裁切/装袋进度；
- 按 SKU 汇总的标准材料包需求、已领数量、来源批次和箱码；
- 配对进度和总订单齐套状态；
- 打印文件、标签、领料单、快递面单及其版本，允许安全重复下载；
- 异常、报废和重做记录；
- 操作人和操作时间。

批次首版状态使用：`READY`（已创建）、`IN_PROGRESS`（生产中）、`COMPLETED`（生产完成）、`ARCHIVED`（已归档）。批次不能通过普通操作硬删除。生产开始前的撤回和开始后的纠错规则在异常阶段单独确认。

## 六、不同岗位的排序原则

生产不存在一条适合所有岗位的万能顺序：

- 打印裁切队列按可配置的纸张布局、尺寸、帧数、模板和刀模组排序；
- 材料领料队列按标准材料包 SKU、推荐箱码和先进先出批次排序；
- 配对队列只处理帧包和材料包均已就绪的 `PU`；
- 打包队列按用户总订单判断齐套，同一地址的全部商品齐全后一次发货。

打印裁切配置至少需要：裁切组、尺寸、目标帧数、每张数量、每件页数、模板、组顺序、组内顺序和启停状态。具体页面和排序算法等裁切方案进一步确认后实施。

## 七、当前代码事实与差异

当前已经实现：

- `SalesOrder -> SalesOrderItem -> CustomizeOrder`，即一次付款一个 `SO`，按数量展开多个 `PU`；
- 旧地址导出会写入 `batchId` 和 `seqNo`；
- 旧帧包导出会按 SKU 建文件夹、生成对照清单和条码清单；
- `ProductionBatch`、`BatchItem`、`FrameInstance` 和 `OrderItemBinding` 有旧模型定义；
- 标准材料包已经具有零件、分装、BOM、`KB` 入库批次和 `BX` 箱码基础。

当前尚未形成目标闭环：

- 生产批次仍由地址/帧包导出的副作用产生，而不是显式创建；
- 旧排序以收件人和商品展示顺序为主，不等于打印裁切排产；
- 重复导出不能保证只是重复下载同一冻结文件；
- 旧库存方法只修改 SKU 汇总数字，没有领取具体 `KB` 批次和 `BX` 箱码；
- 私人帧素材包没有正式 `FP` 实体及重做版本；
- 扫码确认未形成可靠的服务端逐件绑定；
- 没有满足本文件要求的生产批次列表和详情页；
- 旧生产模型缺少完整迁移和统一状态边界，不能直接继续堆叠。

## 八、分阶段实施

### 第一阶段：批次骨架

- 显式创建生产批次；
- 以完整 `SO` 为选择单位；
- 建立硬性阻断与库存提醒；
- 保存批次、订单和 `PU` 冻结关系；
- 建立批次列表和详情页；
- 展示帧包线、领料线、配对和整单齐套的初始进度；
- 保持旧订单和旧批次只读兼容。

**实施状态（2026-08-23）：已完成。** 当前后台已提供独立“生产批次”入口，可以查看候选总订单、生产前阻断原因和材料包缺口提醒；确认提醒后，以完整 `SO` 为单位创建正式 `PB`，一次性冻结全部 `PU`。批次详情会展示总订单、商品、每个 `PU` 的帧素材、材料、配对、打包四条进度，以及按 SKU 汇总的材料包需求。

本阶段的四条进度是后续作业的可靠数据位置，并不表示员工已经能在页面上完成领料、配对或打包操作。具体操作按钮和状态推进属于第二、第四阶段。

### 第二阶段：并行任务

- 建立帧图任务和材料领料任务；
- 根据 SKU 生成领料汇总；
- 领取具体 `KB` 批次和 `BX` 箱码；
- 建立批次暂存和逐件配对；
- 批次详情实时汇总进度。

### 第三阶段：生产文件与排序

- 建立可编辑打印/裁切配置：**已完成配置、候选筛选和批次顺序快照**；
- 按配置生成和冻结打印文件；
- 保存文件版本并允许无副作用重复下载；
- 单独生成帧素材包标签文件；
- 根据真实裁切方案优化 A4 利用率。

### 第四阶段：异常与打包发货

- 失败、报废、缺件、补打和重做；
- `FP` 多次制作尝试和最终有效版本；
- 总订单周转、面单扫描和逐件配齐；
- 统一库存核销、发货、审计和售后反查。

## 九、暂缓确认

- 最终人工/机器裁切方案及刀模细节；当前软件排序规则已确认并可配置；
- 帧素材包标签尺寸、纸张和打印时机；
- A4 空白区域和跨订单拼版优化；
- 批次开始前撤回订单、开始后紧急移出和跨日续作的详细权限；
- 组装完成款的独立生产线。
