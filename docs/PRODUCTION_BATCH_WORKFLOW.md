# 材料包款生产批次与并行作业流程

> 确认日期：2026-08-23；最后实施更新：2026-09-04
> 当前范围：只设计和实施“帧素材包 + 标准材料包”的材料包款生产线；组装完成款属于另一条产线，本阶段不纳入。  
> 文档性质：本文同时记录已确认业务规则、当前代码差异和分阶段目标。标为“目标”的内容不表示代码已经完成。

## 一、简单说明

一次付款形成一个用户总订单 `SO`。总订单中可以有多种商品和多件实体产品，每件实体产品都有独立生产任务 `PU`。同一总订单首版只允许一个收货地址，因此其中所有生产任务必须全部完成后一起发货。

材料包款由两部分组成：

1. 私人帧素材包：根据订单锁定的动画版本打印、裁切并装入小袋，必须绑定具体 `PU`，不能提前作为公共库存生产。
2. 标准材料包：与动画内容无关，可以提前按 SKU 批量组装入库，使用 `KB` 批次和 `BX` 箱码管理。

生产批次 `PB` 是某次主动选择并冻结的一组完整用户总订单。一天可以创建多个生产批次。创建批次和下载文件必须分开：重复下载同一批次文件不能重复建批次、重复推进状态或重复扣减库存。

## 二、已确认业务规则

1. 当前使用 A4 纸打印，现阶段人工裁切，后续可能改用机器裁切。
2. 5x5cm 十二帧目前一张 A4 打印 12 张；二十四帧使用两张 A4、每张 12 张；十六帧使用一张 A4 打印 16 张。
3. 生产顺序由独立“打印与裁切设置”维护，不能写死在代码里，也不直接复用商品展示排序。当前按打印裁切组、组内真实 SKU 和支付时间排序；两级均支持拖拽，详细规则见 `PRINT_PRODUCTION_PLANNING.md`。
4. 帧素材包标签使用单独标签纸打印并贴在帧包上，不利用帧图纸空白位置混合打印。每件实物使用唯一 `FP` 编码；同一 `PU` 重做时递增制作次数，旧码保留并作废。
5. 生产批次创建后，帧图作业和材料领料并行进行；不要求等待帧图裁切完成后才开始寻找材料包。
6. 材料包按“生产批次 + SKU”提前领取并分区暂存，不同 SKU 不得混放。帧包完成后再逐件配对。
7. 一个总订单首版只有一个地址。一个订单内的全部 `PU` 必须作为整体加入同一生产批次，并在全部完成后一起发货。
8. 快递面单与用户总订单绑定。面单可以在生产前准备，最终打包时扫描面单显示该订单应包含的全部产品，全部核对通过后才能发货。
9. 每次主动创建生产批次后，应有独立批次详情页，长期展示批次所含订单、生产件、文件、领料和完成情况。
10. 失败、报废、缺件和重做必须保留追加记录，不能覆盖原生产结果。详细异常流程可以在主生产流程跑通后实施，但数据结构和页面必须预留位置。
11. 首版不为每个普通标准材料包贴单件码；领料通过 SKU、`KB` 批次、`BX` 箱码和数量追踪。扫码配对时从对应 `KB/BX` 实际扣减一套，并把来源批次记录到 `PU`。

## 二点一、已确认的订单阶段

付款状态和生产履约阶段分开保存，页面向员工展示生产履约阶段：

```text
已付款
  -> 创建正式 PB 并自动生成 Word：待处理
  -> 按 PB 导出地址：处理中
  -> 按 SO 绑定面单并锁定地址和订单：待生产
  -> 首次导出 Word 和批次生产总表：生产中
  -> 全部 PU 完成配对并装箱：待发货
  -> 服务端核对通过并确认交付快递：已发货
```

内部字段 `fulfillmentStatus` 使用：`PAID`、`PENDING_ADDRESS_EXPORT`、`WAITING_TRACKING`、`READY_FOR_PRODUCTION`、`PRODUCING`、`READY_TO_SHIP`、`SHIPPED`。创建批次不把付款事实改写成其他含义。

## 三、生产前检查

生产前检查不是重新审核用户内容是否适合制作。内容审核和效果判断应在定制或下单前完成。这里仅检查订单资料是否已经具备生产条件。

### 不能进入生产批次

- 总订单未付款、已取消、处于需要暂停生产的售后状态；
- 总订单没有生产任务，或商品数量与 `PU` 数量不一致；
- 同一总订单中的部分 `PU` 已经进入另一个未完成批次；
- 动画版本、帧图清单或必要文件缺失；
- SKU 不存在或已经停用；
- 收货信息不完整，或同一总订单的生产件出现不一致地址。

### 可以进入但必须提示

- 标准材料包可用数量少于本批次所需数量；
- SKU 尚未确认打印裁切组；确认后可以入批，但必须排到打印队列末尾并持续标记为待现场确认；
- 材料包正在补充，预计可以在帧包完成前备齐；
- 其他不影响冻结订单和开始打印、但可能影响最终配对的临时问题。

管理员可以在看见明确缺口后确认继续创建批次。系统必须保存当时的提醒快照，不能只弹一次提示后丢失。

## 四、目标生产流程

```text
已付款且资料完整的总订单
  -> 选择完整 SO 并执行生产前检查
  -> 创建 PB 生产批次并冻结订单、动画版本、SKU 和地址
      -> 帧图线：生成打印任务 -> 打印 -> 裁切 -> 装袋 -> 帧包完成
      -> 领料线：按 SKU 汇总 -> 推荐 KB/BX -> 领取 -> 批次暂存
  -> 两线汇合：扫描唯一 FP + KB/BX，核对 SKU 后逐件配对
  -> 按 SO 放入订单周转区
  -> SO 下全部 PU 配齐后进入打包队列
  -> 扫描快递面单，再扫描每件产品外包装保留的 FP
  -> 确认发货
```

帧图线和领料线拥有各自的队列与进度，不使用一条顺序强迫所有岗位等待。生产批次是共同边界，`PU` 是两条线最终配对的共同身份。

## 五、生产批次页面

生产后台需要独立的生产批次列表与详情，不再只依靠订单页的批次下拉框。

### 批次列表

- 批次号、创建时间、创建人和状态；
- 用户总订单数量、单件生产任务数量和 SKU 种类；
- 帧包完成、材料已领、已经配对、整单齐全和异常数量；
- 支持按状态、日期和批次号查找。

### 批次详情

- 批次概览和生产前提醒；
- 完整总订单列表，展开后查看订单商品和所有 `PU`；
- 帧图打印/裁切/装袋进度；
- 按 SKU 汇总的标准材料包需求、已领数量、来源批次和箱码；
- 配对进度和总订单齐套状态；
- 打印文件、标签、领料单、快递面单及其版本，允许安全重复下载；
- 异常、报废和重做记录；
- 操作人和操作时间。

批次首版状态使用：`READY`（已创建）、`IN_PROGRESS`（生产中）、`COMPLETED`（生产完成）、`ARCHIVED`（已归档）。批次不能通过普通操作硬删除。生产开始前的撤回和开始后的纠错规则在异常阶段单独确认。

### 页面职责边界（2026-09-03 已实施）

- Vue `/app/admin/orders` 是员工执行生产环节的唯一入口：导出地址、绑定面单、导出生产资料、按页返工均在对应环节完成。
- Vue `/app/admin/production-batches` 是批次总览：创建批次、查看冻结订单、生产文件、材料需求和进度，并跳转到当前订单环节；不重复提供状态推进按钮。旧 `admin-production-batches.html` 已物理删除，仅保留临时 302 兼容深链接。
- “扫码作业”只使用一个统一工作台 `production-scan.html?v=当前版本#环节`。总览、帧包完成、材料领用、单件配对和装箱发货通过 `#overview/#frame/#material/#pairing/#packing` 在同一页面切换，不刷新工作现场。四个旧岗位文件和旧 `?station=` 地址只负责兼容跳转，不能保留页面内容或第二套业务逻辑；版本参数只用于强制浏览器取得最新文件，不代表另一套页面。
- 扫码工作台沿用后台的紧凑工具栏和工作面板风格。页面只展示员工当下需要的批次、操作、结果、队列和异常信息；“浏览器会话如何保存”“服务器如何校验”等实现说明只记录在文档和验收测试中，不作为页面文案展示。
- 员工进入扫码作业后只选择一次“当前工作批次”。该选择保存在本次浏览器作业会话中，环节切换时继续使用，关闭浏览器后需要重新选择。主动清空批次，或原批次不再属于可作业列表时，页面必须同时清除旧队列、领料、配对和装箱内容。服务器仍会在帧包完成、材料来源核对、配对和装箱时独立校验批次，不能只依赖页面选择。
- 四个生产动作独立留痕：帧包完成只更新帧图线，材料领用只预留 `KB/BX` 库存，单件配对才正式扣减一套材料，装箱发货按快递面单核对整笔 `SO`。任何一个动作都不能顺便把其他环节标为完成。
- 材料箱中可以放同一 SKU 的多个 `KB` 批次。扫描箱码配对时，系统只从当前 `PB` 已经领用且仍有剩余数量的记录中按领用时间取用，不得改用箱内其他未领用批次。
- 自动验收命令：在 `content-service` 运行 `npm run check:production-workflow` 检查代码和数据结构，运行 `npm run check:production-scan-ui` 真实打开五个扫码页面并验证无需聚焦输入框的扫码行为。
- 旧 `CustomizeOrder.status` 只保留兼容同步，后台生产环节不再读取它作为事实来源。正式事实来源是 `SalesOrder.fulfillmentStatus`、`ProductionBatch`、`ProductionBatchUnit`、`ProductionFramePack`。

## 六、不同岗位的排序原则

生产不存在一条适合所有岗位的万能顺序：

- 打印裁切队列按可配置的纸张布局、尺寸、帧数、模板和刀模组排序；
- 材料领料队列按标准材料包 SKU、推荐箱码和先进先出批次排序；
- 配对队列只处理帧包和材料包均已就绪的 `PU`；
- 打包队列按用户总订单判断齐套，同一地址的全部商品齐全后一次发货。

打印裁切配置包括：纸张、尺寸、每张数量、模具、模板、打印组顺序、组内真实 SKU 顺序和启停状态。每件页数按 SKU 帧数自动计算。

## 七、当前实施状态

截至 2026-09-08，材料包款正常生产和打印按页返工已经形成首轮闭环：显式创建 `PB`、冻结完整 `SO/PU`、生成 Word、地址和面单、帧线与材料线并行、服务端持久扫码、逐件配对、齐套装箱和事务化发货均已实现。

仍存在但不属于正式路线的旧代码包括 `ShippingBatch`、旧地址/ZIP 导出、旧扫码发货、`/api/inventory/ship` 和旧单件订单状态。它们需要在消费者核对后删除，不能继续扩展。详情见 `modules/admin-production.md` 和 `DOC_CODE_DIFFERENCES.md`。

## 八、员工实际操作顺序

1. 用户付款后，在“订单生产 > 已付款”查看待入批订单，再进入“生产批次”选择完整总订单创建 `PB`。系统立即尝试生成 Word；缺模板的产品会明确列为生成失败。管理员补上传模板后，在“订单生产 > 待生产”再次导出时会自动补生成缺失 Word。
2. 在“订单生产 > 待处理”按 `PB` 导出地址。文件按总订单一行生成，订单进入处理中。
3. 从快递平台取得面单号，在“订单生产 > 处理中”填写总订单对应的快递单号和公司。成功后订单进入待生产并锁定。
4. 在“订单生产 > 待生产”点击“导出生产资料并开工”。第一次成功导出后进入生产中；ZIP 内含按冻结顺序排列的 Word 和一个 `批次生产总表.xlsx`。重复下载不重复扣库存或生成新 `FP`。
5. 进入“扫码作业”选择一次当前 `PB`。打印人员按冻结顺序打印、裁切、装袋并贴唯一 `FP`，然后切到“帧包完成”扫描；其他批次的 `FP` 会被拒绝。重复扫描只显示黄色提醒，不重复登记，也不重复写成功日志。
6. 配料人员切到“材料领用”，扫描 `KB/BX` 并填写数量。系统预留对应库存并把同数量生产件标记为材料已领；此时不做正式消耗，未使用部分可以带原因退回。
7. 配对人员切到“单件配对”，页面会列出当前批次可使用的材料来源。先扫描当前使用的 `KB/BX`，随后连续扫描同规格 `FP`。系统核对生产批次、SKU、帧包状态和已领余额，每成功一件才正式扣减一套材料包并释放一套预留；同一 `FP` 重扫只返回原配对结果。
8. 配对完成后将同一个 `FP` 保留在单件产品外包装。一个总订单有多件时，单件可以先进入待齐套区。
9. 在“装箱发货”中先扫快递面单，再逐件扫外包装 `FP`。错订单、未配对、已作废或重复产品都会被拒绝。
10. 全部产品齐全后页面才开放“确认交付快递并发货”。确认后进入已发货；不能从普通订单页直接手改绕过检查。
11. 如果打印或裁切损坏，在“订单生产 > 生产中”找到对应 `PU` 点击“重印”，只勾选损坏页并填写原因。系统生成新码（如 `FP-02`）和只包含指定页的 Word，旧码立即失效；新文件同时保留在批次总览中。

专项检查命令：`npm run check:production-workflow`。负责人完整模拟产线时，按 `PRODUCTION_MANUAL_TEST_PLAN_STANDARD_6SKU.md` 的四订单、六规格流程执行并记录真实 `SO/PB/FP`。

## 九、编码与生产总表

- `MachineModelSku.id` 是数据库内部 ID，形如 UUID，禁止作为员工可见 SKU 编码导出。
- `MachineModelSku.skuCode` 是稳定的商品规格编码；历史数据已使用现有 `skuBarcode` 补齐，新建 SKU 同时生成两者。
- `KB` 是标准材料包入库批次，`BX` 是材料箱，`FP` 是每件私人帧素材包，`PU` 是每件实体生产任务，`PB` 是生产批次，彼此不能互相替代。
- `LEGACY-KIT-...` 是早期库存迁移后保留的材料包批次码，只用于追溯历史库存；新入库继续使用正式 `KB-...`。
- `批次生产总表.xlsx` 的“单件生产明细”按一个 `PU` 一行记录 `PB/SO/PU/SKU/FP/KB或BX/快递单/Word/各环节状态`；“材料需求汇总”按 SKU 记录需要、已领、已配数量和材料来源。
- 同一批次不因返工额外生成一套 `R02/R03` 生产总表。每次下载的表格都在生产明细和材料汇总中写入“`PB编号 / 返工N次`”核对标记；纸质表保留导出当时的数字，批次详情显示系统当前数字。两者不一致即表示手中纸质清单已经落后。
- 批次详情集中展示返工时间线：返工序号、生产件、原因、重印页、旧 `FP`、新 `FP`、重印文件，以及新帧包完成、重新配对和装箱进度。员工不需要重新打印整张生产清单即可找到变化和下一步动作。
- 首次导出生产资料时尚未领料的行显示“待领用”。批次在线记录是事实来源，员工可以在扫码总览重新下载最新快照；领料或配对后重新下载才会出现实际 `KB/BX`。
